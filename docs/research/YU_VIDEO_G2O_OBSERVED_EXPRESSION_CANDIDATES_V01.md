## 1. 제품 계약

사용자가 자유 키워드를 정한다. 고정된 키워드 카탈로그에서만 탐색하게 하지 않는다. 현재 사용자가 명시적으로 선택한 로컬 CSV 또는 YouTube API 댓글 표본에서 원래 키워드가 직접 포함된 댓글의 동반 단어를 찾아, 출현 댓글 수와 댓글 근거를 함께 제시한다.

- 관측 후보는 선택 출처와 현재 7·30·90일 분석 기간만 사용한다. 로컬 CSV와 YouTube 댓글을 합치지 않는다.
- Unicode NFKC와 소문자로 비교하여 2~40자 문자/숫자 단어를 추출한다. 숫자만 있는 단어와 원래 키워드 구성어는 제외한다.
- 동일 댓글 내 같은 단어 반복은 동반 댓글 1건으로 계산한다. 입력 키워드 포함 댓글과 같은 댓글에서 나타난 건수, 선택 표본 전체에 후보 문구가 포함된 건수를 분리한다.
- 동반 댓글 수 순으로 최대 8개 후보를 보여준다. 후보마다 최대 2개 근거 댓글의 영상명/시간/160자 발췌를 펼쳐볼 수 있다.
- 관측 결과는 단어가 함께 등장했다는 의미일 뿐 의미적 동의어·맥락적 연관성·인기 상승·감성·인과관계의 검증이 아니다. 단순 문자 분리는 조사나 잡음 단어를 추출할 수 있다.
- 사용자 원래 키워드가 포함된 댓글이 0건이면 관측 후보는 0개로 표시한다. 가짜 후보를 만들지 않는다.
- 기존 G2-N 직접 입력, 수동 선택/제외, 원래 키워드만 보기, 사용자가 별도 활성화하는 관련 표현 포함 모드, 중복 제외 집계는 유지한다.
- 기존 음악 사전 예시와 새로운 관측 후보의 출처를 분리해 표시한다.
- 후보 선택/근거 열기는 브라우저 메모리에서만 처리된다. API 호출, 자동 검색어 확장, AI 추론, 영상 다운로드나 저장이 없다.

## 2. 모듈과 입력

모델: frontend/src/features/trend/observedExpressionCandidates.ts
UI: frontend/src/pages/analysis/KeywordTrendExplorerPage.tsx
입력은 자유 키워드, 현재 출처의 댓글 배열, 기간이다.
선택한 데이터나 키워드를 바꾸면 후보가 재계산된다. 새 원래 키워드 적용은 기존 G2-N과 같이 선택 표현·확장 모드를 초기화한다.

## 3. Windows QA

기존 G2-N HEAD에서 분기된 G2-O 브랜치로 깨끗한 Worktree를 전환한다. 로컬 CSV만으로 새 후보를 검증할 수 있다. 실제 API 표본 확인에는 기존 개발용 127.0.0.1:8787 프록시가 필요하며 API 키를 채팅에 공개하지 않는다.

1. 자유 키워드만 적용하고 CSV가 없을 때 관측 후보가 없는지 확인한다.
2. 키워드 음악과 음악 노래 플레이리스트 / 음악 노래 / 노래 등 댓글이 들어있는 CSV를 불러와 노래 후보의 동반 댓글 건수와 전체 표본 포함 건수를 확인한다.
3. 후보별 근거 펼치기에서 실제 CSV 댓글의 영상명/시간/텍스트가 보이는지 확인한다.
4. 노래 후보를 수동 선택해도 원래 키워드만 모드가 유지되고, 확장 모드를 따로 누른 뒤에만 그래프/근거가 확장되는지 확인한다.
5. 후보 선택은 YouTube API 요청을 늘리지 않는지 확인한다.
6. 댓글 출처를 CSV ↔ 실제 API로 변경하면 후보가 현재 출처로 갱신되는지 확인한다.
7. 새로운 자유 키워드와 기간을 적용했을 때 이전 후보와 선택 상태의 일관성을 확인한다.

G2-N Windows QA 5/5는 사용자 보고로 PR #118에 기록되었다. G2-O Windows QA는 아직 미완료. G2-M 세 번째/네 번째 영상 제한 및 초기화도 별도 미검수.
