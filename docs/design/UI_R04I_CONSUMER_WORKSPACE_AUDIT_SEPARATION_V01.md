# UI-R04-I — 사용자 분석 화면과 운영 검증 화면의 책임 분리 v0.1

## 배경 / 사용자 피드백

2026-11-04 사용자: `지금 이런 검증 정보들이 패널까지 차지하면서 화면에 나열되고 있는데, 유저한테는 필요없는 정보들이야.`

R04-G/H를 진행하면서 내부 개발·운영 QA에 해당하는 조회 계획(예상 API 할당량·쿼터·POLICY_HOLD)과 클라우드 증빙(8개 게이트·첫 호출 운영자/승인 상태)을 일반 사용자용 `/analysis/youtube/workspace`에 패널로 추가했다. 이 정보는 소비자의 작업 목표(영상/채널 URL 추가, 그래프 탐색, 분석/비교)와 무관하며 화면 밀도만 높인다.

## UX 원칙

1. **일반 사용자(Client/Consumer)**: URL 붙여넣기 및 링크 드롭, 2.5D 그래프, 대상 선택/관리, 비디오 썸네일 선택적 미리보기, 분석 비교 및 결과에 필요한 간단한 상태만 제공.
2. **데이터 이용자가 실제로 필요로 하는 범위**: 결과가 예시인지 실제인지, 데이터가 없는지, 분석된 표본이 무엇인지 사실대로 표시. 표본 상세는 `데이터 범위 보기`를 눌렀을 때만 렌더한다.
3. **운영자/개발자(Internal/Operator)**: `channels.list` 요청 계획·할당량 추정·클라우드 소유권·인증정보/서버 게이트·보안 증빙 8개·실호출 후보/승인 상태 등은 별도 내부 리뷰 영역에서만 검토한다.
4. **보안과 UI 구분**: 패널을 가린다고 정책이 완화되는 것은 아니다. `POLICY_HOLD`, 첫 실호출 차단, `verifiedCount=0` 등은 기존 코드/계약으로 계속 강제하며 UI 숨김으로 허가를 대체하지 않는다.

## 현재 구현

- `AnalysisWorkspacePage.tsx`에서 R04-G `WorkspaceChannelPreflightPanel` import/render 제거. 내부 R04-H는 R04-G 하위이므로 함께 소비자 라우트에서 제외. 특정 URL/query 파라미터로 숨겨진 디버그 패널을 여는 기능도 도입하지 않는다.
- R04-G/H 순수 계획/검증 함수, 독립 UI 컴포넌트, unit test, 기존 설계 문서는 **삭제하지 않고 유지**한다. 다만 현재는 운영자 인증이 붙은 별도 페이지를 구축하지 않았으므로 내부 진단 UI를 어떤 공개 라우트에도 노출하지 않는다. 개발자는 GitHub PR/설계 문서와 오프라인 테스트로 검수할 수 있다.
- 데이터 품질 자체를 제거하지는 않는다. 기존 `VideoWorkspaceEvidence`·`ChannelWorkspaceEvidence`를 기본 접힌 `데이터 범위` 버튼 아래에서만 렌더하며, 기존 선택/결과 규약과 라우트는 보존한다.
- 일반 대상 카드와 집중 모드 상세에 있던 `정책/수집 계약/메타데이터` 관련 엔지니어링 문구는 사용자용 `분석 정보가 아직 제공되지 않습니다`로 간소화한다. URL 입력만으로 실제 데이터 수집·분석이 이뤄졌다고 표현하지 않는다.
- URL 등록, 브라우저 탭별 2시간 보관, 합성 A/B 비교, 기존 별도 오프라인 검증 테스트, 정책 하드락, 그래프/도킹/썸네일 opt-in 기능 불변.

## QA / 회귀

- 초기 화면 및 CHANNEL/CHANNEL_HANDLE URL 등록 후에도 `공개 채널 메타데이터 사전 검증`·`채널 실조회 준비 상태`·`POLICY_HOLD`·`BLOCKED`·`Y45-E**`가 사용자 DOM에 노출되지 않는다.
- 집중 모드의 그래프·선택 목록·상세에도 운영 검증 패널이 나타나지 않는다.
- 소비자 `데이터 범위`는 기본 접힘, 클릭 시 기존 근거 내용과 표본 수치를 정확하게 표시, 다시 접으면 중첩 데이터 카드가 언마운트된다.
- 자동 회귀: 기존 R04-G/H unit test는 그대로 PASS, 새로운 consumer-route integration test는 URL 등록·그래프·A/B 유지, `fetch` 0건, 운영 진단 미노출 검증.
- 수동 Chrome QA: 1440/900/390/320px, 다크/라이트, 새 영상·채널 URL 등록, 집중 모드, 데이터 범위 열고 닫기, 기존 비교 링크와 선택 상태 확인.

## 추후 별도 내부 운영 도구

실제 운영자용 Admin Console은 향후 서버 측 AuthN/인가 및 감사 로깅이 검증된 뒤 **별도 승인**으로 설계한다. 클라이언트 CSS 숨김, 임의 `?admin=true`, localStorage flag 등의 가짜 접근 제어는 사용하지 않는다. 외부 API와 credential은 그때도 별도 허가 없이 호출하거나 노출하지 않는다.
