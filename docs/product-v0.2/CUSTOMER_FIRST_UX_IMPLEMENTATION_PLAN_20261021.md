## 1. 고객 경험의 단일 목표

고객은 YouTube 홈·검색에서 영상 썸네일에 마우스를 올리고,
1. **한 번 훑어 현재 반응을 이해**하고(빠른 첫 결론),
2. **한 번 클릭해 선택한 영상의 상세를 확인**하며(더보기→Side Panel),
3. 충분한 데이터가 있을 때만 **변화의 이유·과정/주제를 확인**하고,
4. 저장·여러 영상 비교·보고가 필요할 때 웹 워크스페이스로 이동한다.

**고객용 결과는 질문 중심:** “사람들은 무엇을 이야기하나?”, “반응의 방향은?”, “전과 달라졌나?”.
UI에서 바로 답하지 못할 때는 결과를 만들어 내는 대신 불편하지 않은 한 문장 안내만 제공.

**고객 화면에서 제거할 용어:** STATIC_FIXTURE, MOCK_ONLY, Cache HIT/MISS, TTL, Singleflight, RequestId, YU-xx, POLICY_BLOCKED, ENTITLEMENT_LIMITED, QUEUED, sourceRights, 내부 Job 단계/토큰, 기술적 로그.
**고객이 필요하면 확인할 정보:** 분석 대상, 의미 있는 기간, 실제 표본·포함 범위, 마지막 확인 시각, 정보 미제공 여부. 이는 작고 이해 가능한 라벨 또는 세부 펼침 형태로 제공.

### 정직한 표시의 최소 경계

- **운영 고객 빌드에 합성 MOCK 수치를 실제 댓글 분석 결과처럼 배포하지 않는다.** 내부 QA 시뮬레이터/디자인 예시에서만 합성 값을 사용하고 테스터에게는 시연임을 구분한다. 고객 빌드에서 유효한 데이터가 없으면 빈 상태를 보여준다.
- 기존 데이터가 오래되어 현재 트렌드로 오해할 수 있으면 최근 확인 시각을 작게 표시한다. 비교 가능 기간이 없으면 상승/하락 화살표나 ‘급상승’ 설명을 표시하지 않는다.
- 고객의 권한/서비스 지원 상황이 원인이더라도 고객에게 내부 정책 코드를 설명하지 않고 **사실에 맞는** 짧은 결과 제공 불가 안내를 쓴다. 외부 법령/정책이 요구하는 설명은 숨기지 않는다.
- 고객 대상/보유량/기간 등 주장은 서버의 승인된 근거와 일치해야 한다.

## 2. 정보 계층: 고객이 보는 순서

| 레이어 | 고객이 알아야 할 것 | 첫 화면 표시 | 상세 확장 |
|---|---|---|---|
| **Hover: Quick Answer** | 한 줄 요약, 감성 흐름, 주요 주제 최대 2개 | 항상 (확인된 경우) | 단일 ‘더보기’ |
| **Side Panel: Understand Why** | 고정된 선택 대상, 감성·주제·기간별 변화, 근거 | 기본 ‘요약’ 탭 | ‘주제’·‘추이’ 탭, 증거/분석 범위 펼침 |
| **Web Workspace: Compare & Work** | 저장 목록, 영상·채널 비교, 반복 이슈, 장기 관측, 보고 | 필요할 때만 | 기간 필터·비교/저장/공유 |

**동일한 데이터를 반복 소개하지 않는다.** Hover에서 충분히 읽은 제목·긴 수치를 Side Panel 첫 화면에 여러 번 중복 표시하지 않는다.

## 3. Hover Card — Compact First

### 3.1 기본형 설계 가이드(초안)

- Figma 기존 카드 약 356×470px → **새 변형의 목표 가로 336~356px, 세로 260~320px**. 실제 치수는 Figma와 좁은 뷰포트/줌/키보드 검수로 결정.
- **상단:** YOUTOPIA 로고 작은 크기 + 영상/채널 맥락(필요할 때만).
- **주요 결론:** 한국어 1~2줄. 실데이터 승인과 분류/표본 기준을 만족한 경우에만 “OOO 언급이 늘고 있어요” 등 변화 설명.
- **미니 감성 바:** 검증된 긍정·중립·부정의 짧은 가로 stacked bar + 백분율(비교 기준 명확). 단순 요약에서는 원형 차트·범례와 과한 장식을 피함.
- **주요 주제:** 가장 빈번한 논점 1~2개 태그. 없으면 줄 자체를 숨기되 레이아웃 급격한 이동을 방지.
- **작은 기준줄:** 예: “최근 7일 · 분류된 댓글 240개”처럼 실제 사용된 분모를 구체적으로 명시. 지연/오래된 경우 “마지막 확인 어제” 등 최소 단서 표시.
- **단일 CTA:** 항상 의미가 있을 때만 활성화된 ‘더보기 →’. 버튼/카드 위 포인터 이동 기존 안정화 유지.
- 상세 차트 2개 이상, 원시 댓글, 모델 신뢰 점수, 내부 정책 설명, 복수 CTA, 긴 영상 제목 재출력은 Hover 카드에서 제외.

### 3.2 예시(내부 설명용으로만 합성 값)

~~~text
┌──────────────────────────────────┐
│ YOUTOPIA · 영상 반응             │
│                                  │
│ 조리법에 관심이 집중되고 있어요  │
│ 긍정적인 반응이 우세합니다.       │
│                                  │
│ [긍정 ━━━━━┃중립 ┃부정]          │
│ 62%           23%     15%        │
│                                  │
│ [조리법] [재료]                  │
│                                  │
│ 최근 7일 · 분류된 댓글 240개      │
│                         더보기 → │
└──────────────────────────────────┘
~~~

**주의:** 위 수치와 요약은 Mock 설계 예시. 운영 고객에게 해당 영상의 진짜 감성 결과로 전달하지 않는다.

### 3.3 카드가 아닌 전체 홈 페이지의 동작

- Hover 시 0ms 일반 진입 지연이라는 현재 Controller 계약을 유지하되 렌더링 0ms 보장은 하지 않는다.
- 썸네일 → 자기 카드 → 자기 썸네일 반복 진입에서 카드를 유지. 카드 뒤 영상 B 선택 차단, 카드→노출 C 이동 시 대상 전환, 카드 밖 완전 이탈 시 정리.
- 같은 videoId가 화면 다른 위치에 중복되어 있어도 지리적으로 먼 복사본에 잘못 붙지 않는다.
- 카드 하나만 활성화, 바로 뜨는 가벼운 shell과 후속 내용 갱신을 분리. loading→ready 전환 중 폭/높이가 점프하지 않도록 고정 공간/placeholder 사용.
- 카드가 원래 YouTube 클릭/타임라인/미리보기/무한스크롤을 방해하지 않도록 기존 Shadow hit region과 안전 거리 회귀를 유지.
- 초상화 이미지·동영상 제목 중복 등 공간 낭비 최소화. 고객이 원래 YouTube 썸네일을 보고 있다는 사실을 이용한다.

## 4. Side Panel — Summary → Topics → Trends

기존 [98-10 Side Panel](https://www.figma.com/design/00Q6HNjuv02u7Ex4yUzZer/?node-id=1276-217)은 Chrome이 관리하는 폭의 반응형 화면. 현재 약 435px 시안이지만 실제 고정 폭을 강제하지 않는다.

### 4.1 고정된 상단과 기본 요약

- Sticky Header: 사용자가 ‘더보기’로 클릭한 대상의 **짧은 제목/채널명**, 영상/채널 구분 및 닫기. 길면 말줄임과 접근 가능한 전체 이름 제공.
- 탭: **요약(기본) · 주제 · 추이**. '구독'과 '설정'을 첫 탐색 요소로 섞지 않음.
- 기본 화면 첫 viewport: **핵심 결론 한 줄 → 감성 미니바 → 대표 주제 최대 3개 → 변화 신호 한 줄(가능할 때)**.
- 추가 상세: 정확한 관측 기간/댓글 수/제외 또는 근거/신뢰 의미가 중요한 경우에만 ‘분석 범위 보기’ 및 관련 설명 확장.
- 1차 행동을 방해하는 전면 팝업·권한 경고·반복 배너는 기본으로 쓰지 않는다. 필수 사용자 조치는 실제 필요한 순간에만 요청.

### 4.2 주제 탭

- 단순 단어구름보다 고객에게 이해하기 쉬운 **논점 이름 + 관련 댓글 수 또는 언급률 + 감성 방향** 형태의 정렬 목록 우선.
- 각 논점을 누르면 선택된 기간 내 변화/근거·대표 대화(정책 허용 범위)에 접근.
- 세부 주제의 이름이 불확실하면 추정 제목을 만들어 내지 않고 해당 결과를 숨기거나 일반화된 주제명으로만 표시.
- 여러 논점에 하나의 댓글이 포함될 수 있으므로 논점 점유율을 합산해 100%라고 오해시키지 않음. 상세에 필요한 분모 설명.

### 4.3 추이 탭

- 동일 주제에 대해 언급 수(또는 언급률)와 감성 비율을 별도 지표로 제시. 스파크라인/일별 라인 차트는 비교 가능한 데이터가 있을 때만.
- 비교 기간이 확보되지 않았으면 빈 차트·평평한 가짜 선·증가 화살표를 표시하지 않는다. “아직 변화를 보여줄 기록이 없어요”로 간단히 대체.
- 기간 선택은 **실제 제공할 수 있는 범위만** 활성화. 지원하지 않는 기간을 누르면 효과 없는 가짜 필터를 두지 않는다.
- 채널 분석에서는 ‘선정된 영상 N개’의 범위를 명시하고, 채널 전체 여론으로 일반화하지 않음.

### 4.4 Side Panel 대상 고정 계약

- A 카드의 ‘더보기’ 클릭으로 패널 A를 열면 A를 고정. B/C에 Hover해도 패널 A 유지.
- B 카드의 ‘더보기’를 명시적으로 누를 때에만 B로 교체. A의 늦은 응답이나 다른 탭 데이터가 B를 덮으면 FAIL.
- 사용자 제스처 흐름에서 Chrome Side Panel API를 요청하고 tabId/context를 정확히 관리. 설정/실행은 YU-28 승인된 별도 PR에서 검증.
- 새 Side Panel을 열 때 사용자의 YouTube 화면 이동을 요구하지 않는다.

## 5. 웹 워크스페이스 — 의도가 있을 때만 진입

- 채널·영상 저장, 기간 비교, 주제별 반응 추적, 승인된 보고서 생성·공유 등 **시간이 걸리는 작업**으로 역할을 좁힌다.
- 웹 첫 화면은 기술 작업 대시보드 대신 **저장한 영상 / 최근 중요한 변화 / 이어보기** 세 영역 우선.
- 관리자용 Job 상태/가상 실패 토글/정책 강제 설정/QA trace는 고객 화면과 격리한다. 기존 YU-01~12 React 자산은 삭제하지 않고 재배치.
- 구독은 분석 범위·깊이 확장, 조직 역할은 서버 접근 통제라는 원칙 유지. 구독 안내는 정보 이해를 방해하지 않는 시점에만.
- 실제 사용자 데이터 저장·유료 전환·보고서 공유는 후속 정책/기능 승인 없이는 활성화하지 않는다.

## 6. 고객용 문구 사전 — 내부 원인과 분리

| 내부 상태/검증(고객 화면에는 표시 금지) | 고객에게 표시할 짧은 문구(제안) | 금지해야 할 오해 |
|---|---|---|
| READY / 유효한 데이터 | “조리법 이야기가 가장 많아요” + 의미 있는 기간·표본 | 없는 ‘실시간’, 근거 없는 대표성 |
| LOADING_CACHE / 실제 조회 중 | “반응을 확인하고 있어요” | 내부 캐시 알고리즘, 백그라운드 작업 ID |
| CACHE_MISS / 분석 데이터 미확보 | “아직 보여드릴 반응 요약이 없어요” | 실제 큐가 없는데 ‘곧 분석 완료’ 예고 |
| QUEUED/RUNNING / 실제 작업 존재 | “반응을 살펴보고 있어요” | 완료시간 미확정인데 카운트다운/확정 약속 |
| STALE / 유효하지만 과거 정보 | “마지막 확인 2일 전” (사실에 맞게) | 오래된 값을 ‘방금 실시간’이라고 표시 |
| NO_DATA / 단순 미확보 | “아직 분석할 반응 정보가 충분하지 않아요” | 실제 댓글이 0건이라는 단정 |
| COMMENTS_DISABLED / 확실히 확인됨 | “이 영상은 댓글을 확인할 수 없어요” | 추정만으로 댓글 비활성 확정 |
| POLICY_BLOCKED / 접근 불가 | “지금은 이 영상의 분석을 제공할 수 없어요” | 수집 실패와 원인을 허위로 표현 |
| ENTITLEMENT_LIMITED / 기능 범위 밖 | “이 항목은 더 넓은 분석 범위에서 볼 수 있어요” | 무단 결제/가입 유도, 데이터가 있다고 암시 |
| ERROR / 조회 장애 | “지금 결과를 불러오지 못했어요” | 실패를 허위 긍정·부정 비율로 대체 |
| TREND_UNAVAILABLE / 비교기간 없음 | “아직 비교할 변화 기록이 없어요” | 0%나 상승·하락 추이 조작 |
| UNRESOLVED_HANDLE / 정확한 채널 ID 없음 | “이 채널의 반응을 아직 확인할 수 없어요” | 임의 채널 ID 생성 |
| QA_ONLY_STATIC_FIXTURE | 고객용 운영 빌드에 분석 수치 공급 금지. QA 화면에서만 합성 자료 표시 | 합성 수치를 실제 사용자 반응으로 표시 |

**고객 UI에서 기술적 상세를 굳이 설명하지 않는 것**과 **고객이 결과가 실제인지·언제의 데이터인지 오해하지 않도록 하는 것**은 별개의 문제다. 필요한 의미만 남기고 노출 단계·문구를 간결하게 설계한다. 약관/정책이 요구하는 설명은 숨기지 않는다.

## 11. 이 작업의 완료 조건

- 경쟁 서비스의 공개 UX 동작과 추론을 분리한 벤치마킹 문서 존재.
- 현재 승인 Figma 노드와 신규 변형 후보의 차이·정보 우선순위·고객 문구·속도 목표·접근성 Gate 정의.
- YU-27/28/29 및 YU-30~49에 적용할 단계와 승인 경계가 명확함.
- 문서 PR이 현재 개발 코드, Figma, 기존 Draft PR을 수정하지 않았다는 비교 증거.
- Figma 실제 디자인 작업과 React/Extension 구현은 **다음 사용자/디자인 승인 이후의 후속 작업**.

**아직 완료되지 않은 것:** 새 Figma 시안 제작·사용자 시각 승인, 고객 UX 과제 인터뷰, 크롬 실기기 설치형 MV3 최종 테스트, 실제 API/실댓글·구독·결제/출시. 문서에 적은 목표를 실행 PASS로 표기하지 않는다.
