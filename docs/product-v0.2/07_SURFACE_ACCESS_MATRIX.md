## 1. 사용자/역할 정의

- **미로그인 방문자(Guest)**
  - 2026-10-21 **허용된 기본 Hover/Side Panel을 로그인 없이 우선 제공**하는 UX 방향 승인. 실제 데이터 이용권/지원 범위·Guest 조회량/남용 제한은 별도 승인·서버 검증 조건.
  - 제3자 개인/조직 데이터 수정은 금지.
- **개인 고객(Customer Viewer)**
  - 허용된 영상/채널 분석 조회. 본인이 저장한 자료 범위만 접근.
  - **무료 로그인:** 영상·채널 대상 참조 북마크, 본인이 작성한 개인 메모·폴더 제공 방향 승인. 댓글 원문·분석 스냅샷 자동 보관은 금지.
  - **개인 구독:** 기간·대상·비교·추적·보고 기능의 범위를 확대하되 데이터 이용권과 서버 인가는 별개 검증.
- **고객 팀 구성원(Customer Team Member)**
  - 속한 조직이 소유한 프로젝트 중 별도 부여된 자원에 접근.
  - 자신이 플랫폼 관리자가 되는 것은 아님.
- **고객 조직 관리자(Customer Team Admin)**
  - 자기 조직의 멤버 초대·권한·보고서 결재(계약 승인 시)를 관리.
  - 다른 고객 조직과 YUTOPIA 플랫폼의 운영 정보에는 접근 불가.
- **YUTOPIA 플랫폼 운영자(Platform Admin)**
  - 허용된 운영 시스템·정책·수집 Job·구독 장애 조사.
  - 고객 개인정보/원문에 무제한 접근하는 계정이라는 의미 아님.
- **개발·QA(Developer / QA)**
  - 시험 환경에서 fixture·실패/정책 상태를 재현.
  - 운영 고객 UI로 시뮬레이터를 배포하지 않음.

**Guest 기본 Hover/Side Panel 및 필요할 때 고객 로그인(2026-10-21), 무료 로그인 북마크·메모·폴더(2026-10-22)는 승인된 UX 방향**입니다. 구독 비교/추적·조직 협업은 분석 범위 확대 방향만 승인됐으며, 실제 가격/한도·데이터 권리·인증 서버·보관 DB·구독 API는 모두 미구현/미확정입니다. 사용자 선택 없는 저장·결제 자동 실행은 금지합니다.

### 2.1 로그인 위치와 사용자 동선

**추가 승인 — AUTH-SURFACE-01 (2026-10-21): 운영 고객 Chrome 확장에는 개인·조직 고객의 공통 서비스 로그인 진입만 표시한다.** 조직 관리자도 같은 고객 로그인으로 접근하지만 조직 관리 업무는 웹 전용·서버 RBAC 기준으로 제공한다. 플랫폼 운영/정책 관리자 로그인은 플랫폼 **웹** 전용, DEV/QA 인증·시뮬레이터는 격리된 **내부 웹/테스트 환경** 전용이다. 관리자·QA 계정용 로그인 폼/탭/정책 토글을 운영 고객 확장에 추가하지 않는다. [Figma 제품별 책임 맵](https://www.figma.com/design/00Q6HNjuv02u7Ex4yUzZer/?node-id=1334-15)

- Hover/기본 Side Panel은 로그인이나 OAuth 팝업으로 시작하지 않는다. 개인 저장·비교·추적·협업/구독 기능을 명시적으로 선택한 순간 필요한 이유를 설명한다.
- 로그인 취소 시 Guest 허용 데이터와 선택 대상을 보존하고, 로그인 성공 시 동일 탭·고정 대상·원래 업무 맥락으로 돌아가되 저장 API는 서버에서 별도 재인가/확인한다.
- 플랫폼 운영자 로그인과 DEV/QA 환경은 고객 공통 로그인 표면과 분리하고, 실제 역할은 모두 서버가 판정한다.
- 상세 결정 및 테스트는 [Guest Auth UX](./GUEST_AUTH_CONTEXT_RESTORE_UX_20261021.md), [Auth QA](./GUEST_AUTH_ACCEPTANCE_20261021.md)를 따른다.

## 3. API에서 매번 검증할 것

1. **신원:** 서버가 검증한 사용자/세션으로 행동 주체 식별.
2. **범위:** 사용자가 속한 조직과 대상 영상/채널/프로젝트 권한.
3. **역할:** 자료를 조회/저장/수정/승인할 권한.
4. **구독:** 요청 기능의 분석 기간·영상·채널 수 또는 조회량 제한.
5. **플랫폼 권리:** 실제 YouTube API·데이터/파생 계산/보관 이용 조건.
6. **데이터 가용성:** 원문 삭제, 댓글 비활성, 미수집, 오래됨, 정책 차단.
7. **감사:** 중요한 작업의 인증된 행위자, 상태 변화, 시간과 사유.

**허용 순서:** 위 조건 중 필요한 조건이 하나라도 불확실하면 **데이터를 노출하지 않음**. 클라이언트에서 체크박스나 role 문자열을 바꿔도 서버에서 승인되지 않음.

## 4. 고객 UI에서 보여주지 않을 것

- `DEMO_REVIEWER_UNAUTHENTICATED`, QA 사용자의 `EDITOR/VIEWER/DENIED` 전환 토글.
- `RUNNING/PARTIAL/FAILED`의 가짜 Worker 실행 버튼과 원시 감사 타임라인.
- 내부 정책 버전·서버 Stack Trace·접근 토큰·LLM 모델 호출 비밀.
- 실제로 접근할 수 없는 다른 고객의 프로젝트나 비용·결제 정보.
- 법적/정책 차단은 고객에게 설명하되 내부 관리자 운영 버튼을 같이 노출하지 않음.

## 5. 부정 테스트

- [ ] 조직 A 사용자가 조직 B 보고서 URL의 ID를 바꿔도 접근 불가.
- [ ] 고객 팀 관리자가 플랫폼 Admin Console을 열 수 없음.
- [ ] 구독 구매/유료 플랜 문자열 변경만으로 플랫폼 관리 권한이 생기지 않음.
- [ ] 고객이 강제 실패/가용성/권한 시뮬레이터를 찾거나 호출할 수 없음.
- [ ] 요금제가 허용하더라도 정책 차단된 분석 결과는 볼 수 없음.
- [ ] 권한 없는 사용자가 댓글 원문 또는 보고서를 공유·내보내기 할 수 없음.

**현재 상태:** 역할/서비스 API 미구현, 설계 초안과 부정 테스트 항목만 작성됨.
