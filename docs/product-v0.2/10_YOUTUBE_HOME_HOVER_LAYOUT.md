## 1. P0 기준 화면 (데스크톱 홈)

**검증 대상으로 상정하는 상황**

- 데스크톱 Chrome의 YouTube 홈페이지, 화면에 추천 영상 썸네일 **여러 개**가 배치되어 있음.
- 확장 프로그램 YUTOPIA는 **켜져 있음**.
- 사용자는 영상 B 썸네일 위에 포인터를 올림.
- YouTube의 검색·추천·재생 및 기본 썸네일 hover UI를 가급적 방해하지 않음.
- 영상의 분야를 **게임으로 제한하지 않음**(뉴스·음악·브이로그·상품·교육 등).

```text
YouTube 홈 / 브라우저 콘텐츠 (개념 배치)
┌──────────────────────────────────────────────────────────────────────────────┐
│ YouTube 로고      [검색                                  ]       사용자메뉴 │
├──────────────────────────────────────────────────────────────────────────────┤
│ [추천 필터/카테고리]                                                       │
│                                                                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │ 썸네일 A     │  │ 썸네일 B     │  │ 썸네일 C     │  │ 썸네일 D     │       │
│  │              │  │   ⌖ hover   │  │              │  │              │       │
│  └──────────────┘  └──────────────┘  └──────────────┘  └──────────────┘       │
│   제목/채널        제목/채널        제목/채널        제목/채널                │
```

**중요:** 위 텍스트는 설계를 설명하기 위한 좌표 예시일 뿐 YouTube의 실제 현재 DOM/간격·영상 위치를 확정하지 않습니다. 카드가 다른 썸네일을 반드시 겹치지 않을 수 있다고 보장하지 않으며, 화면 공간 부족 시 자동으로 위치를 바꾸거나 카드 폭을 제한해야 합니다.

## 2. 카드 구성 (고객이 보는 것)

1. **헤더**
   - YUTOPIA 브랜드(YouTube 공식 UI와 구별).
   - `영상 분석` 또는 `채널 분석` 구분.
   - 제목/이름은 한두 줄로 줄임, 완전한 텍스트는 접근 가능한 이름으로 보존.
2. **감성 분포 미니 차트**
   - 분석 가능한 댓글 등 실제 분모에 기초한 **긍정/중립/부정**의 막대.
   - 수치가 없거나 정책 차단되면 차트 대신 상태 설명.
   - `YUTOPIA 파생 추정치`라는 출처 안내.
3. **주요 이슈**
   - 많아도 2~3개 짧은 논점만.
   - **관측 표현**과 사실 확인/인과 판단 구분.
4. **브리핑**
   - 1~2문장. 긴 보고서나 내부 상태 코드를 카드에 넣지 않음.
5. **범위/신뢰 안내**
   - 분석 표본 수, 분석 기간 또는 범위, 마지막 분석 갱신 시각.
   - 채널의 경우 선정된 영상 개수·기간을 표시.
6. **더보기**
   - 사용자 클릭으로 Chrome Side Panel을 여는 명확한 CTA.
   - 카드/Side Panel에 동일한 영상/채널 ID가 사용돼야 함.

## 2.1 작업 26 개발 UI와 실사용 UI의 경계

- 26번 브랜치는 위 와이어프레임의 데이터 영역을 Shadow DOM 카드로 구현하고, 고정 가상 분포·2개 가상 논점·1문장 예시 브리핑 및 DEMO/STATIC FIXTURE를 명시한다.
- 실제 YouTube 제목·댓글·통계는 아직 읽지 않는다. 따라서 대상 표시는 검증된 VIDEO/CHANNEL ID이며, 채널 핸들이 아직 매핑되지 않으면 차트를 표시하지 않는다.
- 26번 더보기는 아직 실제 Side Panel로 분석 대상을 전송하지 않고 다음 단계 안내만 제공한다. 27~28번에서 연결한다.
- 브라우저 모의 V8 150/150 PASS와 실제 YouTube 홈 UX-01~22 수용 체크는 별개다. 실제 Chrome 다크/라이트, 포인터 이동, 오른쪽 경계, 기본 UI 간섭 검수를 완료하기 전까지 시안 완성으로 선언하지 않는다.

## 3. 위치 계산 규칙 (후속 코드 구현 가이드)

- **우선 위치:** 활성 썸네일의 우측, 간격 **8~12px (제안)**.
- **공간 부족:** 카드가 화면 오른쪽 밖으로 나가면 왼쪽, 아래, 위의 안전한 위치를 평가.
- **가로 폭:** 첫 설계안은 약 **320~360px (확정 아님)**. 작은 브라우저 창·Chrome Side Panel이 열린 경우 가용 공간 내 자동 축소.
- **세로 폭:** 내용이 긴 경우 최대 높이를 제한하고 카드 내부 스크롤을 검토. 브라우저의 주 스크롤을 차단하지 않음.
- **겹침 방지:** 팝업 아래에 있는 YouTube 버튼·추천 링크 클릭이 불필요하게 막히지 않도록 필요 최소 영역 사용.
- **YouTube 화면 변경:** 카드가 사라진 요소의 좌표를 계속 따라다니지 않도록 연결 앵커 유효성 검사.
- **고정 좌표 금지:** '영상 B는 두 번째 썸네일' 같은 리스트 인덱스로 분석 대상 추정하지 않음. 항상 안정적인 `videoId` 확인.

## 4. 카드의 상태 전이

```text
기본 YouTube 화면
  └─ 썸네일 Hover 시작
       ├─ targetId 식별 실패 → 표시 금지/안내
       └─ 짧은 지연 후 → 분석 요약 로딩
              ├─ READY → 차트/쟁점/브리핑/더보기
              ├─ PARTIAL/STALE → 범위와 갱신시각 경고
              ├─ NO_DATA/COMMENTS_DISABLED → 차트 대신 안내
              ├─ POLICY_BLOCKED → 데이터/구독과 무관하게 차단
              └─ ERROR → 오류 안내, 안전한 재시도
```

- **이전 요청과의 경쟁:** A → B로 Hover 대상이 바뀌면 A 응답이 늦어도 B 분석으로 채워지면 안 됨.
- **빠른 통과:** 우연히 마우스가 지나가는 모든 썸네일마다 서버 데이터를 요청하지 않음.
- **카드로 이동:** 썸네일→분석 카드로 포인터가 이동해도 클릭 가능한 상태를 유지.
- **새로운 Hover:** 다른 영상의 카드가 열려 있으면 이전 카드 종료 후 새 카드만 표시.
- **Side Panel 고정:** B의 더보기를 누른 뒤에는 C를 Hover하더라도 열린 상세 B가 유지.

## 5. 고객·관리자 UI 경계

- **고객에게 제공:** 차트, 논점, 표본, 브리핑, 더보기, 데이터 가용성.
- **고객에게 감춤:** 강제 실패/권한 변경 테스트 버튼, 수집 Worker 로그, 디버그 reasonCode, `DEMO_REVIEWER_UNAUTHENTICATED`.
- **구독 고객:** 추가 기간·영상/채널 비교·저장/보고 기능. 구체 제한·가격 미승인.
- **QA:** 목업 데이터·Hover 지연·오류 상태를 실험하기 위한 별도 개발 도구에서만 임의 설정.

## 6. 후속 프로토타입에 필요한 화면 검증

- [ ] 추천 영상 최소 4개 이상이 나열된 화면에서 **B 썸네일 Hover**.
- [ ] Hover 카드가 **B** 분석으로 표시되고 C/A 데이터 오인 없음.
- [ ] 오른쪽 끝 D 썸네일 Hover 시 카드가 화면 밖으로 잘리지 않음.
- [ ] YouTube 기존 동영상 hover 미리보기/클릭/메뉴와 충돌 최소화.
- [ ] 카드 안으로 마우스 이동, **더보기** 클릭 가능.
- [ ] 더보기 클릭 후 Chrome Side Panel에 B 분석 고정.
- [ ] 카드에서 0/미확정/댓글 비활성/정책 차단 상태 정확 구분.
- [ ] 다크/라이트 YouTube 화면 및 줌에서 텍스트·차트 읽기 쉬움.
- [ ] Tab/Enter/Escape 등 포인터 대체 조작 제공.
- [ ] 소스·분석 댓글 수·기간·시각과 파생 지표 고지가 유지.
- [ ] 실제 YouTube API/외부 LLM 없는 **mock 시연**으로 구현 가능.

**상태:** 26번 Shadow DOM UI 코드 및 격리 V8 모의 150/150 PASS. 위 체크리스트의 실제 YouTube Chrome 수동·시각 검증은 **NOT TESTED**. 픽셀 정합성/접근성 확정 아님.
