## 사례 C01 — 홈 영상 썸네일 Hover (최우선)

**사용자 목적:** 영상을 클릭하지 않고 해당 영상에 나타난 반응을 빠르게 살펴봄.

1. **준비:** YouTube 홈에 서로 다른 영상 A·B·C가 보임.
2. **행동:** 영상 B의 썸네일 위에 마우스를 잠시 올림.
3. **기대:** 영상 B에 대응하는 YUTOPIA 카드가 썸네일 **옆**에 나타남.
4. **카드 내용:** B 제목, 짧은 반응 분포, 주요 논점, 브리핑, 분석 댓글/기간/갱신 시각, **더보기**.
5. **확인:** A나 C의 결과가 B 카드에 섞이지 않으며 영상 재생/스크롤/홈 클릭을 방해하지 않음.
6. **퇴장:** 썸네일·카드에서 포인터가 벗어나면 닫히되 카드로 이동할 때는 깜빡이지 않음.

**완료 조건:** B 대상으로 표시된 카드가 지연·위치·접근성 기준을 충족하고, 데이터가 없으면 가짜 수치를 생성하지 않음.

## 사례 C02 — 더보기 클릭 → F12처럼 브라우저 옆 상세 패널

1. **준비:** 영상 B에 Hover 카드가 열려 있음.
2. **행동:** **더보기** 클릭.
3. **기대:** Chrome의 **확장 Side Panel**이 열림. DevTools(F12) 자체를 열지는 않음.
4. **표시:** 선택한 영상 B의 대상 ID와 제목, 감성 상세, 주제, 근거, 기간, 분석 범위.
5. **고정:** 패널이 열린 상태에서 영상 C에 마우스를 올리더라도 **B 상세 패널은 자동 변경되지 않음**.
6. **명시 전환:** C 카드의 **더보기**를 누르면 비로소 패널이 C로 바뀜.

**완료 조건:** 패널 대상이 클릭한 대상과 항상 일치하고 이전 요청의 느린 응답으로 덮어쓰지 않음.

## 사례 C03 — 채널 항목 Hover

1. 채널 아바타/이름/채널 링크 중 분석 대상 채널을 확실히 식별할 수 있는 요소에 Hover.
2. YUTOPIA 카드가 **영상 단위가 아닌 채널 단위**임을 제목/배지로 구분.
3. 선정된 영상 수, 조회 가능한 관측 기간, 분석된 댓글 범위 명시.
4. 브리핑에서 **채널 전체 시청자의 의견**이라고 일반화하지 않음.
5. 더보기 클릭 시 `CHANNEL` 대상의 패널로 열림.

**불확실한 채널 ID:** `@handle`을 유효한 `channelId`에 매핑할 수 없으면 다른 채널의 분석을 억지로 표시하지 않음.

## 사례 C04 — 다른 썸네일을 빠르게 이동

- **행동:** A → B → C 썸네일을 짧은 시간 안에 연속으로 지나감.
- **기대:** 불필요한 카드·API 호출이 폭증하지 않음.
- **비동기 안전:** A의 분석 응답이 C보다 늦게 도착해도 **C에 A 데이터를 표시하지 않음**.
- **표시:** 동시에 겹친 카드 하나만 유지. 다른 썸네일의 YouTube 기본 hover 동작을 방해하지 않음.

## 사례 C05 — 데이터가 없거나 사용할 수 없음

| 상황 | 고객 화면 | 금지 |
|---|---|---|
| 댓글 비활성화 | “댓글 확인이 제한된 영상입니다” | 감성 0% 계산 |
| 실제로 분석한 댓글 없음 | “분석 가능한 댓글이 없습니다” | 가짜 긍정/부정 차트 |
| 일부만 확보 | “분석 가능한 일부 댓글만 포함” | 전체 결과라고 주장 |
| 오래된 캐시 | 마지막 분석시각과 갱신 필요 고지 | 최신 여론으로 표현 |
| 정책 차단 | “데이터 제공 조건 확인 중” | 결제 유도만으로 해결된다고 주장 |
| 서버 일시 오류 | 짧은 오류/안전한 재시도 | 조용히 다른 영상 데이터 사용 |

## 사례 C06 — 기본 고객과 구독 고객

- **기본 고객:** 허용된 범위에서 단건 요약과 최소 근거·표본 확인.
- **구독 고객:** 더 넓은 영상/채널/기간/비교와 저장·추적 등의 상세 도구.
- **제한 화면:** 구독이 필요한 이유를 **어떤 범위가 추가되는지**와 연결하여 설명.
- **금지:** 미정 가격·이용횟수를 실제 상품처럼 표시하거나 자동 결제를 시작하지 않음.
- **정책:** 구독이 있어도 YouTube 자료 권리나 보존 제한을 우회하지 못함.

## 사례 C07 — 고객/관리자/QA 구별

- **고객:** 감성 요약, 브리핑, 근거/범위와 사용 가능한 구독 기능만.
- **고객 조직 관리자:** 자기 조직의 분석/팀원/공유 설정만(별도 승인된 기능).
- **플랫폼 관리자:** 서비스 내 고객/수집/정책/장애 상태. 고객 카드에 관리 메뉴 없음.
- **개발/QA:** `FAILED` 강제 발생, fixture 교체, `EDITOR` 역할 토글 등 내부 모의 기능.
- **완료 조건:** 고객 Hover·Side Panel에 `DEMO_REVIEWER_UNAUTHENTICATED`, 정책 내부 reasonCode, 강제 상태 토글 노출 없음.

## 사례 C08 — 키보드·이동성·브라우저 UI

- `Tab` 포커스 또는 동등한 진입점으로 Hover 카드의 정보/더보기 접근.
- `Enter`/Space는 실제 클릭과 동등하게 작동.
- `Escape`로 미리보기만 닫고 YouTube 페이지의 기본 키보드 조작에 영향 최소화.
- YouTube 홈의 오른쪽 끝 썸네일은 카드가 화면 밖으로 잘리지 않게 자동 재배치.
- 125%·150% 줌, 다크/라이트 모드, 화면 크기 변화에도 텍스트/차트 판독 가능.
- Chrome Side Panel 너비·좌우 위치는 브라우저/사용자가 관리함. 정확한 360px 오른쪽 고정을 제품 계약으로 약속하지 않음.
