## 1. 현재 코드의 상태

- **기준 커밋:** `344c1e2794c4f6144fa7506f65a17c392487c540`.
- **현재 완료된 것:** React 기반 로그인→채널 동의→프로젝트·수집→대시보드→분석→근거→이슈→로컬 보고서까지 12개 데모 화면.

## 2. 고객·관리자·QA별 경계

| 표면 | 고객이 볼 것 | 고객에게 숨길 내부 기능 |
|---|---|---|
| YouTube Hover | 간략 감성·쟁점·출처/표본·더보기 | 강제 실패 버튼, raw 수집 실행 제어, 디버그 ID |
| Side Panel | 현재 영상/채널 상세 분석·근거·범위·구독 혜택 | 테스트용 VIEWER/EDITOR 강제, 정책 우회·샘플 교체 |
| 고객 워크스페이스 | 저장/비교/모니터링/보고서, 자기 조직 팀 설정 | 플랫폼 전체 사용자·Worker·서비스 비밀 |
| Admin Console | 필요한 운영 정보, 고객 지원·데이터 출처/권한·감사 | 별도 프로덕션 고객 UI에 혼입 금지 |
| Dev/QA | 모의 API, 오류/삭제/권한 전환, fixture | 사용자에게 배포 금지 |

| YU-05 | 수집 진행/실패 | 고객에게는 최신 분석/갱신 상태만; Job은 Admin | 강제 RUNNING/FAILED/PARTIAL 버튼 QA |
| YU-06 | 대시보드 | Side Panel 요약/고객 분석 화면 | 데이터 강제 상태 셀렉터 QA |
| YU-07 | 댓글 분석 | Hover 요약의 파생 카드/Side Panel 상세 | 합성 댓글 원문은 QA 전용 표시 |
| YU-08 | 전후 비교 | Side Panel 구독 확장/고객 워크스페이스 | 게임 패치 고정 기간은 fixture 유지 |
| YU-09~10 | 근거 검증/상세 | 고객용 ‘왜 이런 분석인가?’·리뷰 권한자 심사 | 주장 승인 시도·가용성 강제 변경은 QA |
| YU-11 | 이슈 관리 | 고객 조직의 협업(구독 기능 후보) | 가짜 감사 actor·강제 역할 전환 QA |

**데이터 정확성 불변식 유지:** `null` vs 확인된 `0`, 실제 원문 vs `SYNTHETIC`, 관측 발언 vs 검증 결함, Kanban `COMPLETED` vs 주장 검증 vs 보고서 정식 승인.


## 7. 실제 API·데이터 이용 권한 차단 게이트

- YouTube API를 통한 감성 등 파생 지표에는 **일반 API 허가 외 추가 심사/Analytics 허용**이 필요할 수 있다. 승인 전에는 실제 API 원문으로 감성을 계산·배포하지 않는다.
- **공식 근거:** [YouTube Derived Metrics Policy](https://developers.google.com/youtube/terms/derived-metrics-policy), [Developer Policy Guide](https://developers.google.com/youtube/terms/developer-policies-guide).
- 사용자의 Google/OAuth 비밀번호를 수집·저장하지 않는다. 소유자 전용 접근이 필요할 때만 적절한 최소 범위 동의를 고려.
- 고객의 영상 Hover와 서비스 수집 권한을 혼동하지 않는다. Hover 자체가 데이터를 무조건 수집·캐시할 사용권을 부여하지 않는다.
- 구독은 YUTOPIA의 기능 권한을 늘릴 뿐 플랫폼의 사용권 제한을 해제하지 않는다.
