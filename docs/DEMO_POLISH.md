# 시연 화면 이동과 분석 도우미 기록

관리자 메뉴의 공개 게임 목록과 공개 화면의 관리자 전용 메뉴를 연결한다. 로그인 기본 이동은
게임 목록이며, 허용된 명시 복귀 경로를 보존한다. 일반 이메일/관리자 ID 로그인과 공개 탐색
진입을 구분하고 기존 SessionProvider와 로그아웃을 재사용한다. 이동 시 인증을 새로 만들지 않는다.

기존 코드의 session.generation은 포커스/세션 확인 때마다 증가하는 조회 무효화 값이다.
이를 대화 삭제 기준으로 삼던 effect와 상태 재확인의 답변 교체를 제거했다. 기록 공급자는
라우트 밖에 두고 상태 조회와 분리한다. 게임 이름용 중복 상세 요청도 제거한다.

기존 로그인/내 정보 응답에 이미 검증된 SessionIdentity의 authVersion과 관리자 generation을
각각 authVersion/adminGeneration 문자열로 노출한다. 숫자 정밀도 손실을 피하고 서버의 실제
계정 ID·비밀번호 변경 버전·관리자 로그인 세대로 기록을 구분한다. 새 API 경로나 DB 변경은 없다.
세대 정보가 없는 이전 응답에서는 메모리 기록만 쓰며 저장 기록을 임의 추정해서 복원하지 않는다.

같은 탭 sessionStorage에는 형식 버전/계정 범위와 질문 ID·요청 UUID·처리 상태·응답 텍스트만
저장한다. 최대12항목/64000 UTF-16 코드 단위(최대128KB), 응답12000 코드 단위다.
쿠키·비밀번호·키·CSRF·인증 헤더를 저장하지 않는다. 손상/접근 실패는 메모리로 처리하고
응답은 일반 텍스트로 렌더링한다. 실제 인증 확인 전과 일시 확인 불가 동안 기록을 숨기고 보존한다.
확정된 로그아웃·401·계정/관리자 세대 변경은 기록을 삭제하고 진행 중 답변의 늦은 반영을 막는다.

새로고침 중 pending 요청은 처리 결과 미확인으로 복원하고 자동 재전송하지 않는다.
완료 기록 복원·재열기·이동·상태 확인은 답변 API를 호출하지 않는다. 현재 탭에서 사용자가 명시적으로
미확인 요청을 다시 누를 때는 기존 requestId를 재사용한다. 새 고정 질문만 새 요청을 만든다.
화면 기록 삭제는 서버 예산/영수증·Redis와 연결하지 않는다. 기존3질문·관리자·CSRF·호출 한도는 유지한다.

패널은 화면 안에 높이를 제한하고 대화 영역을 따로 스크롤한다. 마지막을 읽는 중이면 새 항목으로
이동하고, 과거를 읽는 중이면 위치를 유지하며 최신 답변으로 버튼을 제공한다.

검증은 변경 관련 프론트 테스트, 타입 검사/프로덕션 빌드, 기존 인증 응답의 집중 단위 테스트와
프로덕션 정적 파일을 사용하는 모킹 Chromium4개다. tools/verify_demo_polish.py는 이 최소 범위를
명시한 배포 증거를 남긴다. 실제 인증/DB·Redis·운영 수용이나 전체 보안 감사 결과로 확대하지 않는다.
실행 예: frontend에서 pnpm build, 저장소에서 python3 tools/verify_demo_polish.py.
챗봇은 프로젝트 소개용 LLM이고 실제 게임 분석/RAG는 연결하지 않는다. 기존 /demo는 보존한다.
