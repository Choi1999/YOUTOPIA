## 6. Adversarial review findings — 2026-10-27 KST

**P0 (corrected on isolated branch):** G28-2 initially required `sender.frameId===0` even for messages sent by the extension-owned Side Panel page. Chrome's `runtime.MessageSender` states `frameId` is optional and set only when `sender.tab` exists. A legitimate `chrome-extension://<extension-id>/sidepanel.html` READ sender may omit both `tab` and `frameId`. The original code replied `UNTRUSTED_SENDER` in a direct isolated reproduction, so the selected pin could not be reliably displayed. The corrected check requires the exact extension ID and `chrome.runtime.getURL("sidepanel.html")`, no sender tab, and permits an absent or top-level frame ID; a subframe and forged sender remain rejected. New regression case explicitly models omitted fields. Reference: https://developer.chrome.com/docs/extensions/reference/api/runtime#type-MessageSender

**P1 (corrected on isolated branch):** Previously the panel's `readPin` checked the 2-hour TTL only during reads; the displayed selection could remain on screen past its expiration without any interaction. An in-panel expiry timer now triggers a fresh READ and clears the stale selection when the time arrives; timers are cancelled upon refresh, tab switches and disposal. The panel DOM regression test now simulates expiry with no `storage.onChanged` event.
