# UI-R04-AD-3/4 — 선택 상세·반응형 도킹 통합

기준: 2026-11-06 KST
부모 Draft PR #93: 40e51084007a543c4746ad32e4430a107ccb0e26
범위: React 워크스페이스 UI/UX만 변경, 운영 Spring/Google/YouTube API 및 배포·병합 미승인

## 1. 현황과 설계 근거

UI-R04-AD-1/2에서 그래프·도킹 대상 목록·선택 상세·compact fallback Board가 동일한 선택 및 도킹 너비 상태를 공유하게 되었다.

기존 WorkspaceFocusMode의 오른쪽 상세는 썸네일, 제목, ID, 출처 상태, 편집 입력 2종, 외부 링크와 삭제를 한 번에 세로로 표시해 좁은 화면에서 스크롤이 길고 편집·삭제 버튼이 항상 노출됐다.

또한 workspace-focus.css는 <=1100px에서 좌우 패널을 overlay로 표시하지만 React의 inNarrowViewport()는 <=720px에서만 목록·상세 상호배타를 실행했다. 721~1100px 태블릿에서 두 오버레이가 동시에 열려 그래프를 크게 가릴 수 있었다.

이번 작업은 기존 전체 화면 집중 모드/도킹·키보드/포인터 너비 계산을 재사용하고, 이 두 불일치를 정리한다.

## 2. AD-3: 상세 정보 구조

상단 선택 대상 요약(즉시 표시): 검증되지 않은 영상/채널 타입·이미지 또는 placeholder·사용자 지정 별칭이 우선인 제목·등록된 canonical ID·제공자 정보 미확인 안내.

아래 세 가지 native details/summary 구획:
- 기본 정보: 처음 열림. 채널 인증/핸들 미해결 상태, 합성 테스트 출처(개발 진단 전용), 실제 분석 데이터 미제공, canonical URL.
- 표시 제목·이미지 편집: 처음 닫힘. 열었을 때만 기존 사용자 제목 저장 form과 채널 이미지 URL 저장 form을 사용. 이미지 URL 입력만으로 외부 이미지 요청을 시작하지 않으며 기존 별도 이미지 미리보기 동의가 필요.
- 대상 관리: 처음 닫힘. 외부 YouTube 링크와 등록 대상 제거 버튼. 원래의 URL 검증/대상 제거 기능 유지.

탭 키/Enter/Space가 기본 HTML disclosure 동작을 지원하며 별도 숨은 관리 API는 생기지 않는다. 선택한 canonical 대상이 바뀌면 detail 구획이 새 대상의 기본 접힘/열림 상태로 리셋된다. 기본 신원 상태는 보이는 상태로 남겨 출처가 미확인인 대상을 오인하지 않게 한다.

## 3. AD-4: 일관된 반응형 패널

- >=1101px: 기존 좌측 목록/중앙 그래프/우측 상세 3열과 12px 리사이즈 핸들, 최소 너비 및 사용자 크기 선호를 유지. 패널 열기/닫기에 따라 CSS grid가 그래프에 남는 공간을 자동 배분한다.
- <=1100px: CSS overlay 경계와 React의 단일 overlay 전환 경계를 일치시킨다. 목록 열기 시 상세 닫기, 상세 열기 시 목록 닫기. 데스크톱에서 두 패널이 열려 있던 상태로 폭을 줄일 때는 목록을 닫고 선택 상세를 남긴다. 현재 선택·북마크·리사이즈 저장값은 유지한다.
- 721~1100px: overlay 너비를 컨테이너 폭의 48%/380px 이하로 제한하여 중앙 그래프 영역을 가능한 한 노출.
- <=720px: 하나의 하단 sheet만 활성. 동적 viewport(dvh), 화면 높이 상한, safe-area 하단 여백, 스크롤 내부 격리를 반영해 OS 화면 키보드/낮은 화면에서 panel 내 스크롤이 작동하고 배경 본문으로 스크롤이 전파되지 않도록 한다.
- 좁은 화면으로 전환해도 선택된 target detail을 버리지 않으며 layout 저장·초기화의 기존 sessionStorage 형식(youtopia-focus-dock-layout-v1)은 수정하지 않는다.

## 4. 기존 기능/보안의 유지 조건

- URL 입력/드롭, 그래프 선택/그룹/북마크, 목록 검색/삭제/전체 비우기, 사용자 별칭과 채널 이미지 동의 보존.
- 선택 대상만 기본 정보/편집/관리 가능; 다른 URL의 제목·이미지/등록을 임의 변경하지 않음.
- 일반 사용자 화면에는 UI-R04-AC의 개발 QA 버튼·합성 상태 제어가 없어야 한다. /analysis/youtube/workspace/diagnostics는 기존 Vite DEV 명시 플래그가 없으면 열리지 않는다.
- POLICY_HOLD 및 liveCallsAuthorized=false, 운영 API/Cloud/DPAPI 계정 경계 그대로. React UI 변경 이외의 작업 없음. provider 실제 요청 0건.
- 이후 진짜 제공자 신원·연관관계/메타데이터가 연결되더라도 그 전에는 '미확인' 경고를 제거하지 않는다.

## 5. 자동 테스트와 수동 Windows Chrome QA

자동 계약:
- AD-3: 기본 제목·ID·미확인 안내는 즉시 노출, 편집/삭제 폼은 접힌 상태. 펼치면 사용자 제목/이미지 저장과 삭제가 기존대로 실행되고 별도 이미지 동의 및 세션 저장 규칙 유지.
- AD-3: 다른 노드를 선택하면 임시로 열린 편집/관리는 새 선택 대상에 대해 자동 초기화.
- AD-4: 820px tablet과 390px mobile에서 최대 한 개 overlay. 목록->상세 동작·기존 선택 유지. 1440px desktop 복귀에서 양쪽 도킹·리사이즈 가능. 다시 tablet 축소해도 그래프·선택·제공자 미확인 상태 유지.
- 기존 URL/그래프/별칭/이미지, React 전체 Vitest, TypeScript, Vite, extension/shared contracts, pinned Spring test-only Vite HTTP 3+6, Windows Check-only 모두 exact-head PASS 필요.
- 자동 CI가 통과해도 실제 Windows Chrome에서 화면의 잘림·키보드·스크롤·모바일 에뮬레이션을 사용자가 확인하기 전까지 수동 QA PASS라고 주장하지 않는다.

로컬 QA 순서:
1. 별도 PR exact HEAD로 작업 트리를 만들고 frontend에서 pnpm install --frozen-lockfile, pnpm dev --host 127.0.0.1 실행한다.
2. /analysis/youtube/workspace 접속, 영상 2개와 채널 1개 등록. 선택 상세 기본 정보 및 미확인 표시 확인.
3. '표시 제목·이미지 편집'을 열어 사용자 별칭 저장. 이미지 URL은 별도 동의 전 로드 없음 확인.
4. '대상 관리'를 열어 YouTube 원본 링크/제거를 검수. 다른 노드 선택 시 관련 편집 UI 접힘 상태로 초기화 확인.
5. Chrome DevTools responsive 1440/1024/820/720/390px에서 목록·상세·그래프 패널을 열고 닫으며 중앙 그래프 가시성/겹침/스크롤을 확인.
6. 1440에서 마우스/키보드로 패널 너비를 조절하고 820으로 줄였다가 확대해 사용자 배치·선택 상태가 안전하게 복원되는지 확인.
7. 페이지 새로고침 후 사용자 별칭/그룹/북마크와 기존 넓이 설정 보존, 진단 기능 분리·실 Google 요청 미발생 확인.
