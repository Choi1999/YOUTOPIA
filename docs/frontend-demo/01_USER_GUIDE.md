## 1. 먼저 알아둘 세 가지

- **모든 화면은 데모입니다.**
  - 로그인·채널 승인·댓글 수집·감성 분석·근거 검증·AI 보고서를 **브라우저에서 흉내** 냅니다.
  - 실제 YouTube 계정 로그인, API 요청, 데이터베이스 저장, 외부 AI 호출은 하지 않습니다.

- **새로고침하면 진행 상태가 사라집니다.**
  - 프로젝트·수집·검토·보고서 상태는 브라우저 메모리에 있습니다.
  - 정상 사용자 여정을 끝낼 때까지 **F5/새로고침을 누르지 마세요.**
  - 나중에 오류·복구 테스트에서만 새로고침을 사용하세요.
  - 다크/라이트 선택과 “이메일 기억”은 별도로 남을 수 있습니다. **이메일 기억은 로그인 유지가 아닙니다.**

- **화면의 성공과 실제 서비스 완료는 다릅니다.**
  - 수집 `SUCCEEDED` ≠ 분석 완료.
  - 칸반 `COMPLETED` ≠ 주장 검증.
  - 보고서 `SIMULATED_SUCCESS` ≠ 정식 승인·저장·공유.

## 2. 실행 방법 — Windows / VS Code

1. VS Code를 열고 **터미널 > 새 터미널**을 선택하세요.
2. 다음 명령어를 실행하세요.

```powershell
cd C:\Projects\YOUTOPIA\frontend
corepack pnpm dev
```

3. 터미널에 보이는 `Local` 주소를 브라우저로 여세요.
   - 보통 `http://localhost:5173/`.
   - 이미 사용 중인 포트라면 `5174` 등으로 바뀔 수 있으므로 **실제 표시된 주소**를 이용하세요.
4. 의존성이 설치돼 있지 않아 실행에 실패하는 경우 **다른 Codex 설치/테스트 작업이 진행 중이지 않을 때** 아래를 먼저 실행하세요.

```powershell
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

5. 사이트를 종료하려면 서버가 실행 중인 터미널에서 `Ctrl + C`를 누르세요.

**기준 환경:** Node.js `24.18.0`, pnpm `12.9.1` (개발 시 검증된 버전). 실제 컴퓨터의 버전·실행 오류가 다르면 [README](../../frontend/README.md)를 먼저 확인하세요.

## 4. YU-01 — 로그인·회원가입·비밀번호

**접속:** `/login` (또는 `/`).

- **정상 로그인**
  - 데모 계정으로 로그인 → “로그인되었습니다.”와 **P0-1 데모 화면 열기** 링크 확인.
  - **로그아웃** → 다시 로그인 양식이 나오는지 확인.

- **잘못된 로그인**
  - 올바른 이메일에 틀린 비밀번호 입력 → **“이메일 또는 비밀번호가 올바르지 않습니다.”**
  - 실제 서버 계정과는 관계없습니다.

- **이메일 기억**
  - **로그인 상태 유지** 체크 후 정상 로그인.
  - 새로고침/다시 방문했을 때 이메일 입력란이 기억되는지 확인하세요.
  - **중요:** 이 체크박스는 현재 `youtopia-login-email`만 저장합니다. **실제 로그인 상태가 유지되지 않습니다.**

- **회원가입(가짜 계정)**
  - **회원가입하기** → 이메일과 8자 이상 비밀번호/확인 입력.
  - 현재 페이지에서 데모 계정이 만들어지고 그 계정으로 로그인할 수 있습니다.
  - **다른 비밀번호 / 기존 이메일 / 8자 미만**의 오류 안내도 확인하세요.
  - 새로고침하면 만들어진 계정은 사라집니다.

- **비밀번호 재설정**
  - **비밀번호 찾기** → 데모 계정 이메일·새 비밀번호·확인 입력.
  - 저장은 현재 페이지의 React 메모리에만 적용됩니다.
  - 이메일 소유권 확인·메일 발송은 없습니다.

- **SSO / Google**
  - **SSO 로그인** 탭에서 회사 이메일 입력 후 클릭 → 서버 연결이 필요하다는 안내가 나와야 합니다.
  - **이메일 로그인** 탭으로 돌아와 **Google로 계속하기** → OAuth 서버가 필요하다는 안내가 나와야 합니다.
  - 실제 SSO/Google 로그인창이 열리면 **예상과 다른 동작**입니다.

- **승인 흐름**
  - **Google 연결 · 권한 승인 →** → **시뮬레이션 승인**.
  - 승인 화면에서 **시뮬레이션 연결 완료** 확인.
  - **관측 프로젝트 만들기 →** 로 다음 화면 이동.

- **거부 흐름**
  - YU-02에서 권한 검토를 열고 **거부** 선택.
  - “권한 요청이 거부되었습니다.” 메시지 확인.
  - **권한 다시 검토**를 누르면 검토 화면으로 돌아갑니다.

- **취소 흐름**
  - 권한 검토 중 **취소** 선택.
  - “권한 검토가 취소되었습니다.” 메시지 확인.
  - **권한 다시 검토**로 복귀.

- **만료 흐름**
  - 승인 후 YU-03에서 **승인 만료 시뮬레이션** 선택.
  - 승인 완료 UI가 더 이상 표시되지 않아야 합니다.
  - **다시 연결** → YU-02로 돌아갑니다.

- **연결 해제**
  - 승인된 YU-03에서 **연결 해제**.
  - YU-02로 돌아가 미연결 상태를 확인합니다.

- **직접 주소 진입**
  - 새 탭에서 `/connect/youtube/complete`를 바로 열거나 승인 화면을 새로고침.
  - **“승인 상태를 확인할 수 없습니다.”** 등 보호 안내가 정상입니다.
  - 실제 승인이나 토큰이 복원되면 안 됩니다.

- **공개 데이터 우회 경로**
  - YU-02에서 채널 승인 없이 사이드바 **프로젝트** 클릭 → YU-04로 이동할 수 있습니다.
  - 이는 공개 영상 관측에 Google 권한이 필수인지 **아직 결정하지 않았기 때문**입니다.
  - 실제 데이터 접근이 승인됐다는 뜻은 아닙니다.

- **빈 양식 테스트**

  - “입력 내용을 확인해 주세요.”와 오류 개수/필드 표시가 나와야 합니다.
  - 페이지가 수집 화면으로 이동하면 안 됩니다.

- **중복 영상 테스트**
  - **입력 취소**로 기본 데모 양식 복구.
  - 선택 영상 2를 선택 영상 1과 같은 **업데이트 트레일러**로 변경.
  - 제출 시 **“같은 영상을 중복 선택할 수 없습니다.”** 확인.

- **날짜 테스트**
  - 사건 날짜를 다른 날로 변경 → 데모 고정 사건일 `2025-03-25` 검증 메시지.
  - 관측 시작일이 종료일보다 늦으면 제출 차단.
  - 기간에 전 `2025-03-11~03-24`, 후 `2025-03-25~04-07` 창이 모두 포함되지 않아도 차단.

- **입력 취소 vs 양식 비우기**
  - **양식 비우기:** 입력을 빈 상태로 만듦.
  - **입력 취소:** 프로젝트를 초기화하고 기본 NEXUS 데모 값으로 복귀.
  - 둘 다 실제 서버에 저장하지 않습니다.

## 15. 모든 화면에 공통으로 확인할 사항

- **테마 전환**
  - 화면 위쪽 **다크 / 라이트** 버튼을 각각 누르세요.
  - 색상뿐 아니라 글씨·배지·차트·버튼이 읽기 쉬운지 확인합니다.
  - 테마는 새로고침 후에도 유지될 수 있습니다.

- **화면 이동**
  - **← 이전 단계**는 브라우저의 실제 이전 방문 기록으로 이동합니다. 항상 고정된 YU 번호로 이동하는 것은 아닙니다.
  - 왼쪽 사이드바에서 **대시보드, 프로젝트, 채널 연결, 댓글 분석, 트렌드 관측, 근거 검증, 이슈 관리, AI · 보고서** 메뉴 확인.
  - 상태를 준비하지 않고 나중 화면으로 이동하면 보호 메시지가 나오는 것이 정상입니다.
  - **게임 검색 / 설정**은 현재 비활성화된 기능입니다.

- **크기와 스크롤**
  - 개발자 도구의 반응형 화면 크기를 **1024, 1280, 1440, 1600px**, 높이 **900px**로 바꿔 확인하세요.
  - 1024~1279px: 왼쪽 메뉴가 **64px 내비게이션 레일**.
  - 1280px 이상: **208px 사이드바**.
  - 내용이 길면 세로 스크롤은 정상입니다. **가로로 잘린 버튼이나 숨겨진 핵심 내용**은 오류로 기록합니다.

- **키보드**
  - `Tab`으로 이동했을 때 포커스 테두리가 보여야 합니다.
  - `Enter` 또는 `Space`로 버튼을 조작할 수 있는지 확인합니다.
  - 로그인 계정 대화상자는 `Escape`로 닫고 원래 버튼으로 포커스가 돌아오는지 확인합니다.
  - 로그인 이후 앱 화면에서 `Tab` → **본문으로 건너뛰기** → `Enter`를 확인하세요.
  - 자동화된 axe 검사는 과거 통과 보고가 있지만 **수동 스크린리더 테스트는 별도로 필요**합니다.

- **새로고침·잘못된 링크**
  - 프로젝트·권한·검토·보고서 상태가 자동으로 “완료” 처리되지 않아야 합니다.
  - 존재하지 않는 URL은 404 안내 또는 안전한 보호 화면으로 처리돼야 합니다.
