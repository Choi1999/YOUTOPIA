# 프론트와 DB 조회 API 연결

이 브랜치는 팀 서비스 기준 커밋 `49652cee779ef0338965c3495eb0fd78eb244072`에서 시작한 프론트 변경입니다. 백엔드 변경은 `codex/youtopia-backend-db-link-20261127`에 따로 있습니다. 두 브랜치를 병합하거나 운영에 배포하지 않습니다.

## 연결 구조

브라우저 → 같은 출처의 `/api/v1` Spring API → 권한이 제한된 PostgreSQL 조회 풀 순서로 접근합니다. DB 주소·계정·비밀번호를 React 코드나 `VITE_*` 변수에 넣지 않습니다. 세션과 요청 예산은 기존 Redis 계약을 유지합니다.

개발용 Vite 프록시는 `127.0.0.1`의 Spring 포트만 사용합니다. `YOUTOPIA_TEST_HTTP_PORT`로 포트를 지정할 수 있으며 기본은 `28080`입니다. 실제 운영 연결 여부는 서버 설정과 승인된 조회 뷰·권한을 별도로 확인해야 합니다.

## 이번 연결 내용

- 게임 검색·필터·페이지의 이동 문맥 유지와 지연 검색 응답 경합 방지.
- 게임 탐색·대시보드에서 검색어만 지우면 나머지 필터를 유지해 첫 페이지를 조회한다. 전체 조건을 초기화하면 진행 중인 검색도 취소한다. 두 동작은 일반 목록 GET을 사용한다. 검색의 100자 한도는 `GameQuery`와 같이 유니코드 코드 포인트로 검사한다.
- 현재 페이지에 행이 없더라도 응답의 `totalElements`에 게임이 있으면 결과 건수와 첫 페이지 복귀 방법을 표시한다.
- 게임 상세 → Steam·YouTube·반응·키워드·이벤트 → 상세·목록 복귀.
- 게시 영상 날짜·페이지·기간을 URL로 복원하고 최근 기간 전체 목록을 조회.
- 게임별 YouTube 화면에서 게임 상세 조회가 HTTP 503으로 실패해도 카탈로그와 영상 조회 뷰를 사용하는 게시영상 API는 별도로 조회한다. 상세 정보와 게시영상 목록은 각각의 조회 결과를 표시한다.
- 게시 영상에서 기존 영상 관측 API로 이동하고 목록으로 복귀.
- 게시 영상 전체 관측·게시일 확인·선택 기간의 분모 구분. 누락·미래 게시 시각과 수집 성공 시각을 혼동하지 않음.
- 기존 USER 전용 G11 연결 영상 조회를 게임 문맥에서 호출. 기본 비활성·권한 오류·조회 결과를 구분.
- 순위·CCU·영상 차트 선택 상태 복원, 지역별 두 원순위 표시, 키보드 동작 보완.
- Steam 순위 시작일의 선택지와 기본값은 마지막 관측 시작일에서 정확한 주 단위로 최대 12주 안에 있는 원천 관측만 사용한다. 중간 수집 주차가 누락되어도 `RankingChartService`의 범위 검증을 만족한다.
- 실제 게임 DTO의 반응·이벤트 가용성과 Steam·YouTube 관측 요약 표시.
- 로그인 후 기본 이동을 회원 대시보드·관리자 화면으로 구분하고, 접근하려던 허용 경로가 있으면 해당 문맥으로 복귀. 외부 주소·다른 권한 영역으로의 복귀는 거절.
- 관리자 이용 현황에는 기존 이용통계 API가 반환하는 일별 가입 수와 집계 기준일을 표시한다. 가입 기록만 있는 기간과 가입·활동 기록이 모두 비어 있는 기간을 구분한다.
- 관리자 회원 목록에서 상세로 이동한 뒤 돌아올 때 계정 상태·검색어·페이지를 유지한다. 회원 검색어는 관리자 화면의 메모리에만 보관하며 브라우저 주소에 기록하지 않는다.

반응·키워드·게임 이벤트 화면의 진입과 게임 문맥은 연결되지만, 실제 분석 데이터 API는 아직 없습니다. 미지원 화면을 분석 완료로 간주하지 않습니다. YouTube 분석 데모 및 Steam 학습 출력을 임의로 실데이터로 대체하지 않습니다. 프로젝트·근거·이슈·보고서 저장, G12 가속도 산식, 외부 메타데이터·댓글 읽기는 이 브랜치에서 활성화하지 않습니다.

## 백엔드 호환성

기존 날짜 조회 요청은 그대로 유지합니다. 새 전체 기간 목록은 `scope=period` 계약을 사용하는 기능이며 새 백엔드가 필요합니다. 새 `summary`가 없는 응답은 '요약 미제공'으로 표시합니다. 지원되지 않은 계약의 오류를 빈 목록이나 0으로 바꾸지 않습니다.

기존 로그인·CSRF·USER/ADMIN 분리와 관리자 읽기 전용 정책을 유지합니다. G11은 공개 API로 바꾸지 않습니다. 이 브랜치가 운영 정책이나 조회 뷰 활성화를 승인하지 않습니다.

## 재현 가능한 검증

Node 24 이상과 저장소에 고정된 pnpm 버전을 사용합니다.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm exec playwright test --config=playwright.db-link.config.ts
```

`playwright.db-link.config.ts`는 합성 HTTP 응답을 사용하는 브라우저 회귀입니다. 게시 날짜·페이지 재진입/새로고침/뒤로가기, 영상 관측 이동, 없는 게임, 미지원 분석과 G11 권한 경계를 확인합니다. 실제 DB 통합 테스트로 보고하지 않습니다.

`db-publications` 브라우저 검증에서는 격리 PostgreSQL의 게시 영상 1건을 기간 전체 목록에서 열고, 같은 영상의 저장된 누적 조회수 1,000회와 1,200회를 Spring을 통해 확인한 뒤 목록으로 복귀합니다.

실제 Spring·합성 PostgreSQL·Redis·Chromium 검증은 백엔드 브랜치의 `프론트 DB 연동 격리 검증` workflow가 고정된 프론트 커밋을 테스트 폴더에 구성하여 수행합니다. Git 병합 없이 테스트합니다. 해당 실행 결과를 확인하기 전에는 통합 검증 성공으로 판단하지 않습니다. 운영 데이터·운영 계정·배포 검증은 별도입니다.
