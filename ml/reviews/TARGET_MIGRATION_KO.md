# taxonomy v0.5의 학습·서비스 계약 이관

현재 기준은 SOURCE.json에 고정한 분류 브랜치의 v0.5 / 지침 v1.2.0이다. 해당 브랜치는 읽기 전용 기준으로 사용했으며 병합하거나 수정하지 않았다. 공개 가능한 사전·지침·코드만 작업 브랜치에 반영한다. 실제 70건 파일럿 원문·키·원장과 감사 산출물은 저장소 밖 비공개 경로에 둔다.

## 변경 범위

| 연결 | 이전 구현 | 현재 v0.5 구현 |
|---|---|---|
| 주석 | 상위 항목과 감성 중심 | leaf_id, 원문 근거, target, scope, 강도, source_opinion_id 보존 |
| 분류 헤드 | 12부모 × 4감성 또는 미리보기 4감성 초안 | 71 leaf × 독립 긍정·부정 = 142개 |
| 같은 leaf의 양극성 | 하나의 혼합 출력으로 축약 | 양쪽 라벨·근거 유지, 혼합은 파생 집계 |
| 다른 leaf의 양극성 | 사운드 혼합 등으로 축약 | 음악 긍정·더빙 부정의 독립 결과 유지 |
| 일반 대상 | 세부 항목 추정 또는 부재와 혼동 | 해당 UNSPECIFIED 평가로 보존, HOLD/내용 없음과 분리 |
| 검수 이력 | 옛 리뷰 수락과 새 세분류 확인이 섞일 위험 | source_review_acceptance와 reclassification/classification_review 분리 |
| 이관 | 새 구조를 추정해 덮어쓸 위험 | consolidated v2 어댑터, 정확한 원본 사본과 감사·제외 목록 |
| 집계 | 상위 항목만 남거나 의견 수를 리뷰 수로 셀 위험 | leaf 양극성, 파생 혼합, 고유 상위 리뷰 수를 별도로 계산 |
| 오래된 모델 | 매핑만 바꿔 재사용할 위험 | 구형 계약·정책·라벨 해시 불일치 차단, 분류 헤드 재학습 |

사전의 실제 예: SOUND.MUSIC_BGM / VOICE_DUBBING / SFX / UNSPECIFIED, OPERATIONS.TRANSLATION, GAMEPLAY.HIT_FEEL, USABILITY.SETTINGS_ACCESSIBILITY. 미리보기에서 임의로 제안했던 코드명을 현재 코드로 취급하지 않는다. taxonomy.json과 지침은 원본 파일 해시가 일치한다.

## 실제 파일럿 검증 결과

고정 원본 manifest 10개 파일과 제공된 검증기를 격리 확인했다. 70개 리뷰, 옛 활성 의견 112개에서 이관한 새 활성 의견 118개, HOLD 7개, 등록 leaf 71개 중 관측 leaf 65개다. 원문 해시·근거 위치·분리 이관·감성/상위 항목 보존·HOLD·제외·집계가 검증됐다.

이 결과는 모델 정확도가 아니다. 파일 기록상 기존 리뷰 수락은 70건이고 새 AI leaf 분류의 사용자 확인은 0건이다. 모든 파일럿의 learning_eligible=false를 유지하며 임의 승인하지 않는다. 이 70건은 수정본을 포함해 학습·검증·최종 시험에서 제외한다. 학습 가능한 클래스 수를 등록 leaf 수나 이 파일럿 관측 수로 표현하지 않는다.

## 기존 자료와 독립 정답

- 이미 v0.5로 재분류된 파일은 import-pilot-v05로 읽는다. 원문·target·scope·강도·source_opinion_id·근거·HOLD·제외를 보존하고 학습 제외 registry 초안을 만든다.
- 구형 파일에는 migrate가 정확한 원본·옛 승인 원장을 보존하고 새 leaf를 비운 대기 작업만 만든다. 실제 재분류를 자동 수행하거나 옛 상위 분류의 승인을 새 leaf에 복제하지 않는다.
- 독립 학습 데이터는 실제 사람 검수 범위를 원장에 연결하고, 미해결·미적용 수정·명시적 학습 제외를 보존한다. 원장 지문은 신원 인증이나 정답의 타당성을 자동 보증하지 않는다.
- 실제 파일럿 70개 키 목록은 비공개 registry에만 둔다. 고정 원본/키 집합 해시·건수와 일치해야 한다. 다른 기준 수립 파일럿이 있으면 해당 배치도 대조해 추가한다. 총수를 예전 50+10으로 고정하지 않는다.
- 고정 기반 ELECTRA 인코더는 검증 후 재사용할 수 있지만 이전 48개 또는 4감성 헤드를 142개 모델로 해석하면 안 된다. 데이터·모델·지표의 taxonomy/policy/label mapping/input 해시를 새로 고정한다.

## 시험하는 경계

합성 회귀는 음악/더빙, 일반 스토리 약한 긍정/전개 속도 부정, 충돌/접속/로딩, 길찾기/설정/타격감/조작, UNSPECIFIED/HOLD, 같은 leaf의 양극성, Unicode 코드포인트 근거를 검사한다. 실제 원본 검증과 합성 학습 시험은 별도로 보고한다. 강도는 보존 메타데이터이며 현재 모델이 강도나 근거 추출까지 학습한 것은 아니다.

## 서비스·RAG 계약

현재 웹의 frontend/src/features/analysis/model/analysisSnapshot.ts는 YouTube 영상/댓글용 analysis-v1-candidate다. 이 전체 감성 3개 값에 Steam leaf 집계를 넣거나 실제 모델이 연결됐다고 표시하지 않는다. 화면 디자인은 유지한다.

후속 DB/API는 적어도 다음을 보존해야 한다.

- 모델·taxonomy·label mapping·전처리 정책과 입력 범위 버전
- 게임·기간·언어 범위의 원본 스냅샷, 리뷰 키와 수정 버전
- 의견 ID 및 분리된 의견의 source_opinion_id, leaf_id, 원래 긍정·부정, 근거·대상·조건
- 원본 수·분석 가능 수·평가 없음·HOLD·실패와 모델 빈 예측의 구별
- 한 리뷰/수정/스냅샷/모델/leaf/감성 중복 적재 방지와 파생 혼합의 별도 표시

같은 leaf에 긍정·부정이 둘 다 있으므로 감성 한 칸을 덮어쓰는 저장 구조로 되돌리면 안 된다. 구체 DDL·운영 SQL은 작성·적용하지 않았다. 기존 DB의 실제 컬럼·최소 권한·새 적재 경로는 이번에 확인하지 않았으며 자동 전송도 미구현이다.

summarize는 로컬 수치 계약이다. 동일 버전·스냅샷을 검사하고 leaf별 양극성과 상위 고유 리뷰 수를 유지한다. 기간·언어가 다른 데이터를 같은 스냅샷 ID로 잘못 제공한 것을 자동 판별하지 못하므로 생산자가 고정 범위를 지켜야 한다. 의미상 작성자 중복이나 시장 전체 대표성을 보증하지 않는다.

RAG는 같은 스냅샷·수정 버전의 수치와 원문 근거를 따로 연결해야 한다. 현재 분류기는 근거 추출기가 아니므로 예측 점수만으로 인용문을 만들지 않는다. GPT/Gemini 실제 비교, 운영 DB 전송, 서비스 API·화면 연결·RAG 검색/답변 생성과 브라우저 회귀는 후속 작업이다.
