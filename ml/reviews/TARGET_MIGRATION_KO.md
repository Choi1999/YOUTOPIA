# 세부 평가 대상 기준으로의 변경

현재 변경은 학습·출력 구조를 세부 대상에 맞춘 구현이다. 최신 확정 라벨 전체와 실제 재분류 데이터까지 완료됐다는 뜻은 아니다. 참조 대화 읽기 도구가 본문을 반환하지 않아 사용자가 전달한 제한된 미리보기만 확인했다.

## 확인된 문제와 변경

| 연결 | 이전 구현 | 현재 구현 |
|---|---|---|
| 주석 | `aspect_code + polarity` | 상위 항목 + `target_code` + 감성 + 원문 근거, 의견 ID 유지 |
| 학습 대상 | 큰 항목 단위의 48개 출력 | 고정 분류표의 세부 대상 × 감성, 출력 수 동적 결정 |
| 상반된 감성 | 음악 긍정·더빙 부정이 사운드 혼합으로 축약 | 음악 긍정·더빙 부정을 각각 학습·출력 |
| 리뷰 내부 혼합 | 큰 항목에 하나 | 같은 세부 대상 내부에서만 혼합 집계, 원래 의견은 보존 |
| 상위 요약 | 하나의 상위 감성 | 세부 대상·감성 쌍 목록과 대상별 건수 유지 |
| 모델 선택·평가 | 48개라는 가정 | 데이터에 봉인된 실제 세부 라벨 수·support로 계산 |
| 모델/데이터 재사용 | 같은 상위 분류로 읽힐 가능성 | 구형 v1 모델·데이터·실험 거부, 새 정답으로 재학습 필요 |
| 파일럿 제외 | 예전 50+10 고정 | 최신 확인 원본별 배치 목록·해시·실제 ID, 총수 추정 금지 |
| 집계 | 추후 연결 예정 | 오프라인 세부 집계 구현, DB 적재·웹 연결은 미구현 |

`taxonomy.json`의 세부 코드와 `UNSPECIFIED`는 구현 제안이다. 미리보기의 분리표 자체도 제안으로 표현돼 있으므로 확정본으로 승격하지 않았다. 기본 상태는 `draft`이며 실데이터 학습을 차단한다. 실제 확정본은 `--taxonomy`로 지정하고 버전·출처·상위 항목별 확정 상태·세부 대상별 확정 상태를 기록한다. 루트의 상태만 바꿔 미확정 운영·지원이나 비어 있는 세부 항목을 감출 수 없다. 승인 상태는 사람이 확인한 사실의 기록이며 해시가 내용의 타당성을 대신 판단하지는 않는다.

## 기존 자료 이관

1. 최신 전체 분류표와 재분류 원본을 회수한다. 대화에서 한 실제 검수 이력을 유지하며, 기존 파일의 미검수 표시만으로 검수하지 않았다고 말하지 않는다.
2. 원본·검수 원장을 복사해 새 작업 디렉터리를 만든다. `migrate`는 입력 파일을 바꾸지 않으며 정확한 원본 두 파일과 해시를 보존한다.
3. 의견 ID·원문·근거·기존 감성·기존 검수 표시를 보존하고, 새 세부 대상은 비워 재분류 대기 상태로 만든다. 코드가 과거 사운드 라벨을 BGM으로 자동 대체하지 않는다.
4. 실제 새 분류와 근거를 적용한다. 의견을 나눠야 하면 기존 의견과의 연결을 별도로 기록한다. 원래 한 의견에서 새 의견 여러 개를 임의 생성해 승인하지 않는다.
5. 수정된 내용에서 새 승인 후보를 생성해 실제 검수 범위를 연결한다. 기존의 상위 항목 검수는 보존되지만 그것이 새 세부 대상까지 검수했다는 뜻은 아니다. 미확정·경계·미적용 수정은 보류한다.
6. 새 taxonomy/policy/label 해시로 데이터셋과 네 학습 조건을 다시 만든다. 기존 기반 ELECTRA 인코더는 검증된 경우 재사용할 수 있으나, 이전 48개 분류 헤드를 새 세부 라벨로 해석하면 안 된다.

미리보기에서 보인 사례에 대한 회귀 시험은 합성 문장으로 작성했다. 실제 파일럿 4·53·57·69번 원본을 회수해 재분류한 결과라고 주장하지 않는다. ‘약한 긍정’과 같은 강도 표현은 주석 원본에 있으면 그대로 보존하지만, 현재 네 감성 출력이 강도까지 학습·검증했다는 의미는 아니다. 최신 확정 규칙에서 강도·경계·평가 없음/판단 불가 규칙이 바뀌었는지 확인해야 한다.

## 서비스·RAG 연결 검토

현재 웹의 `frontend/src/features/analysis/model/analysisSnapshot.ts`는 YouTube 영상/댓글 분석용 `analysis-v1-candidate`다. 현재 합성 fixture의 전체 긍정/중립/부정 3개 값은 Steam 세부 대상 분류와 다른 계약이다. 이번 변경에서 이 수치를 Steam의 음악·더빙 결과로 바꾸거나 기존 데모 화면에 실제 모델이 연결됐다고 표시하지 않았다.

후속 DB/API 계약은 적어도 모델·taxonomy·정책·원본 스냅샷·리뷰 수정 버전, 리뷰/의견 ID, 상위 항목, 세부 대상, 감성, 처리 상태를 보존해야 한다. 대분류와 감성만 저장하는 배열로 변환하면 정보가 다시 사라진다. 개념적으로 `리뷰 결과`와 `리뷰별 세부 대상 결과`를 나누고, 동일 리뷰/수정/스냅샷/모델/세부 대상의 중복 적재를 막아야 한다. 실제 운영 DB에 이런 컬럼·테이블이 존재하는지, 현재 계정에 필요한 최소 권한이 있는지는 이번에 확인하지 않았다. DDL·GRANT·운영 SQL 적용은 하지 않았다.

`summarize` 산출물은 RAG 연결 전의 로컬 수치 계약이다. RAG는 같은 데이터 버전의 세부 집계와 원문을 연결해야 하며, 예측만으로 ‘음악은 좋고 더빙은 나쁘다’는 근거 인용을 생성하면 안 된다. 현재 모델은 근거 추출기가 아니고 `evidence_spans`는 null이다. DB 자동 전송·검색·응답 생성·실제 웹 렌더링은 별도 작업이다.

## 실제 학습 재개 전 남은 항목

- 최신 전체 분류표와 실제 재분류 파일·검수 이력·전체 파일럿 배치 회수
- 운영·지원 등 누락된 세부 기준, 범용/미명시 대상, 항목 경계, 감성 강도 확정
- 세부 대상별 별도 학습/검증/고정 시험 정답 수 및 오류 비용 점검
- KcELECTRA 실가중치·L4 환경 검증과 새 정답 재학습
- DB 전송·서비스 API·화면·RAG의 같은 버전 연결 및 격리 회귀

실제 GPU 학습과 운영 변경은 기존 보류를 유지한다. 최종 분류표를 확보하기 전 합성 시험 통과를 실제 분류 정확도나 배포 승인으로 쓰지 않는다.
