# Codex 적용 지침 — taxonomy v0.6 / guideline v1.3.1

먼저 현재 checkout의 `AGENTS.md`와 `ai/review_labeling/CURRENT.json`을 읽는다. 이어서 이 디렉터리의 `GUIDELINES_KO.md`, `taxonomy.json`, `CURRENT.json`의 `scope_policy`, `pilot100_review.md`, `pilot100.json`을 확인한다. 버전 포인터와 실제 파일이 일치해야 한다.

## 교육 효과 제외 정책 연결 — v1.3.1

`CURRENT.json.scope_policy` → `education_effect_exclusion_v1.json`을 라벨링 프롬프트·정답 변환기·예측 검증·집계에서 함께 읽는다. 정책 ID는 `EDUCATIONAL_EFFECT_OUT_OF_SCOPE_20261128`이다. 명시적 범위 제외는 일반적인 미등록 대상의 UNSPECIFIED/HOLD 처리보다 먼저 적용한다.

- 교육 효과는 신규 태그·후보·활성 의견·HOLD를 만들지 않는다. 기존 다른 분류로 우회하지 않는다.
- 해당 문자열은 `excluded_spans`와 원문 입력에 보존한다. 제외 사유, 정확한 오프셋, `retain_in_model_input=true`, `span_negative_training_eligible=false`를 유지한다.
- 같은 리뷰의 다른 범위 내 평가는 유지한다. 교육 효과 외 범위 내 평가나 미해결 의견이 없을 때만 내용 없음으로 처리한다.
- `USABILITY.LEARNING_GUIDANCE`는 튜토리얼·게임 설명·안내의 품질로 유지하며, 교육 효과의 대체 태그로 쓰지 않는다.
- taxonomy v0.6과 73개 코드 매핑은 그대로다. 최신 가이드 v1.3.1과 기존 파일럿의 주석 버전 v1.3.0을 구분한다(`pilot_annotation_guideline_version`). 새 가이드 버전을 과거 파일럿에 덮어써 재검수 완료로 표현하지 않는다.
- 체크포인트·분석 결과에는 taxonomy/가이드 버전뿐 아니라 적용한 scope 정책 ID·버전·해시도 남겨 같은 조건으로 비교한다. 이 커밋은 분류 계약 갱신이며 분석기 실행 코드가 자동 갱신·배포되었다는 뜻은 아니다.

## 전달된 자료의 범위와 상태

이 버전은 독립 세부 라벨과 **100건의 라벨링 파일럿**을 전달한다. 실제 분류기 학습, GPU 실행, 분석 DB·서비스 DB 연결, 서버 배포 완료를 의미하지 않는다. 다른 브랜치나 이미 실행 중인 Codex 작업은 새 커밋을 명시적으로 가져와야 하며, 원격 브랜치에 파일이 있다는 이유만으로 checkout이 갱신되지는 않는다.

| 구분 | 유지해야 하는 상태 |
|---|---|
| 기존 1–70번 | 과거 사용자 승인 이력과 AI 세분류 검수 상태를 구분. 새 버전 이관으로 AI 재분류를 사용자 검수 완료로 승격하지 않음 |
| 신규 71–100번 | 사용자가 AI 초안을 검수하여 수정·승인한 30건. 내용 없음·제외·보류 승인도 포함 |
| 보류 의견 | 기존 7개와 75번 1개, 총 8개 HOLD 유지. 활성 감성 정답으로 변환 금지 |
| 92번 | Steam 비추천 메타데이터를 참고한 효과음 부정의 사용자 승인 예외. 원문 단독 감성 정답이 아님 |
| 전체 100건 | 기준 수립용 파일럿. 훈련·최종 시험 제외, `learning_eligible=false` 유지 |
| 검수 방식 | AI 초안에 대한 사용자 검수. 독립 2인 라벨링이나 독립 평가용 gold로 보고하지 않음 |

## 코드와 연결할 계약

1. `python3 ai/review_labeling/v0.6/validate.py`로 파일 해시·100건 원문·근거 오프셋·라벨 사전·검수 상태·이관·집계 검증을 수행한다. 검증 통과는 자료 계약 검증이며 학습·서버 통신 검증이 아니다.
2. 기존 코드의 taxonomy loader, 라벨 목록, 정답 변환기, 예측 JSON schema, GPT/Gemini 프롬프트, 지표 코드, DB 저장 계약이 `CURRENT.json`의 버전을 사용하도록 연결한다.
3. 모델 출력 단위는 **`leaf_id`**다. 상위 속성만 예측하는 기존 모델을 세부 라벨 모델로 간주하지 않는다. 실제 라벨 수는 `taxonomy.json`에서 읽고 이전 버전의 수를 하드코딩하지 않는다.
4. `pilot100.json`의 원문과 주석을 함께 읽는다. `held_annotations`는 활성 정답에서 제외하고, `excluded_spans`는 원문에서 삭제하지 않는다. 서로 다른 분석 상태인 내용 없음·HOLD·처리 실패를 별도 값으로 유지한다.
5. 분리한 의견의 `target`, 근거, 감성, 조건을 각각 저장하고 `source_opinion_id`로 원래 주장과 연결한다. 분리 전 복합 대상 설명을 자식 의견에 그대로 복제하지 않는다.
6. 모든 파일럿 리뷰 키와 해당 리뷰의 수정본을 훈련·최종 시험에서 제외한다. 전처리 이후의 중복·근접 중복 본문도 누출 검사를 한다. 파일럿을 개발 예시나 출력 검증에 사용했다면 그 결과를 미관측 시험 성능으로 보고하지 않는다.
7. 실제 훈련 자료의 leaf별 표본 분포를 확인하고 학습·평가 가능한 범위를 정한다. 등록되어 있다는 이유만으로 그 항목을 학습 완료·성능 검증 완료로 표시하지 않는다.
8. 체크포인트에 taxonomy 버전·해시, 라벨 ID 매핑 해시, 전처리 버전, 입력 필드 범위, 데이터 분할 식별자를 저장한다. 추론과 서비스 집계에서 같은 계약을 확인하고 불일치를 조용히 흡수하지 않는다.

## 원문 단독과 메타 참조 조건

기본 분석은 리뷰 원문에서 평가 대상을 찾고 감성을 판독한다. Steam `voted_up`를 개별 속성 감성으로 복사하지 않는다. 92번만 이번 사용자 검수에서 **`voted_up=false`를 참고한 효과음 부정**으로 승인되었다.

- 92번의 대상 근거와 감성 판정 근거를 분리하고, 메타 참조 사실·원문 단독 확정의 한계·사용자 승인 이력을 저장한다.
- 이 사례를 text-only 감성 정답으로 내보내지 않는다. 텍스트만 제공한 모델이 메타 참조 부정을 예측하지 못했다는 이유로 원문 감성 오답으로 계산하지 않는다.
- 앞으로 평가용 자료에 비슷한 사례가 생기면 text-only 감성 평가 대상과 metadata-assisted 평가 대상을 구분한다. 대상 추출 평가 여부와 감성 평가 여부도 따로 정할 수 있다.
- 자체 NLP·GPT·Gemini를 비교할 때는 모두 동일한 입력 조건을 제공한다. 메타 참조 실험이면 같은 메타 필드·값·설명을 모두 제공하고, 텍스트 단독 실험과 별도 결과로 저장한다.
- 이 예외는 특정 파일럿의 승인된 판정이다. 전체 데이터에 ‘비추천 → 모든 속성 부정’ 규칙을 적용하는 근거가 아니다.

파일럿 전체는 최종 시험에서 제외되므로 92번을 포함한 파일럿 수치로 모델 간 우열을 결론 내리지 않는다.

## 난이도 결과를 서비스에 표시할 때

서비스 표시 문구:

> 난이도 평가는 해당 게임 이용자들의 체감 의견입니다. 게임마다 이용자층·숙련도·선호가 달라, 이 결과만으로 게임 간 절대 난도를 비교할 수 없습니다.

난이도 라벨은 주관적 경험이다. 높은 난도는 긍정일 수도 있으며, 어려움을 즐기는 문맥을 부정으로 바꾸지 않는다. 난도 설정 기능의 호평과 난도 자체의 평가는 별개다.

게임마다 이용자층·장르 선호·숙련도·진행 단계·모드·작성 당시 플레이시간이 다르다. 서비스는 난도 부정률만으로 게임의 절대 난도 순위를 만들거나 게임 간 우열을 설명하지 않는다. GTFO처럼 높은 도전을 선호하는 이용자가 선택했을 가능성이 있는 경우도 고려하되, 게임 이름만으로 모든 이용자나 작성자의 선호를 단정하지 않는다.

집계에는 다음 정보를 함께 전달한다.

- 게임·기간·언어·수집 범위와 고유 리뷰 표본 수.
- 난도에 대한 긍정·부정·복합 및 미해결 수와 사용한 분모.
- 원문에서 확인한 조건, 진행 단계·선택 모드 등 확보된 정보와 미상 여부.
- 작성 당시 플레이시간과 수집 당시 누적 플레이시간의 구분. 플레이시간을 숙련도와 동일시하지 않음.
- 조건 차이와 누락 정보로 인한 비교 한계. 자료가 없으면 추정값을 채우지 않음.

## 모델 비교와 결과 저장

- 자체 NLP·GPT·Gemini는 동일한 고정 시험 자료·라벨 정의·입력 조건·정답 변환 정책을 사용한다. taxonomy나 메타 입력 조건이 다른 실험을 같은 F1 표에 섞지 않는다.
- AI로 생성한 초안을 사용자가 승인한 것과 독립 라벨링 정답을 구분한다. 같은 AI가 만든 초안에 대한 비교를 독립 gold 평가라고 주장하지 않는다.
- leaf별 Precision·Recall·F1·support, Macro·Micro F1, 오류 사례, 적절한 혼동표·학습 곡선을 저장한다. 표본이 없는 라벨은 N/A로 표시하고 평균에 포함하는 정책을 명시한다.
- 서비스 집계는 고유 리뷰 수를 기준으로 계산한다. 여러 leaf나 양쪽 감성에 들어가는 같은 리뷰를 독립 리뷰 여러 건으로 세지 않는다.
- 원본 수·전처리 통과 수·분석 수·구체 평가 없음·HOLD·처리 실패와 데이터·모델·taxonomy 버전을 함께 저장·전달한다.
- 분류 자료 검증, 코드 구현, 학습 실행, 모델 평가, 서버 간 통신, 서비스 배포의 완료 여부를 각각 보고한다.

원문과 주석에는 제삼자의 리뷰가 포함되어 있다. 이 저장소에 들어 있다는 이유로 원문에 별도 재배포 라이선스가 부여된 것으로 간주하지 않는다.
