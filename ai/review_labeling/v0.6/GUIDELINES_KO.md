# 한국어 Steam 리뷰 평가 라벨링 v1.3.2 / taxonomy v0.6

2026-11-28 범위 정책 갱신. 리뷰에 실제로 표현된 평가 대상과 감성, 근거, 조건을 기록한다. 게임의 강점·단점과 시장 인사이트는 여러 리뷰를 집계한 후 해석하며, 개별 리뷰 라벨에 그 결론을 미리 넣지 않는다.

## 교육 효과의 범위 제외 — v1.3.1

- `CURRENT.json`의 `scope_policy`가 가리키는 `education_effect_exclusion_v1.json`을 함께 적용한다. 정책 ID는 `EDUCATIONAL_EFFECT_OUT_OF_SCOPE_20261128`이다.
- 게임을 통해 현실 지식·교육·학습 효과를 얻었다는 평가는 이번 프로젝트의 라벨링 범위에서 제외한다. 교육 효과 태그, 활성 의견, 신규 분류 후보 또는 그 이유만의 HOLD를 생성하지 않는다. `UNSPECIFIED`나 다른 항목으로 우회 배정하지 않는다.
- 해당 원문과 정확한 제외 구간·오프셋은 `excluded_spans`에 사유 `OUT_OF_SCOPE_EDUCATIONAL_EFFECT`로 보존한다. `retain_in_model_input=true`, `span_negative_training_eligible=false`를 유지한다. 교육 효과 언급을 원문에서 지우거나 부정 감성으로 바꾸지 않는다.
- 같은 리뷰에 번역·스토리 등 다른 범위 내 평가가 있으면 그 평가는 유지한다. 다른 범위 내 평가나 미해결 의견이 전혀 없을 때만 이 프로젝트 기준의 내용 없음(`NO_CONCRETE_EVALUATION`)으로 처리한다. 처리 실패를 내용 없음으로 바꾸는 규칙이 아니다.
- `USABILITY.LEARNING_GUIDANCE`는 유지한다. 이 항목은 게임의 조작·규칙·목표·아이템 등을 이해하도록 돕는 튜토리얼·설명·안내의 품질이다. 현실 지식을 배우는 교육 효과와 구분하며, ‘학습’이라는 단어만으로 일괄 제외하거나 대체 분류하지 않는다.
- 등록 세부 라벨은 73개로 동일하므로 taxonomy는 v0.6을 유지한다. 기존 파일럿 100건의 원문·주석과 주석 당시 guideline v1.3.0은 보존한다. 이 패치가 기존 주석을 새 기준으로 재검수했다는 뜻은 아니다.

## 파일럿 출처와 실험 분할 — v1.3.2

`CURRENT.json.training_role_policy` → `training_role_policy_v1.json`을 정답 변환기·분할기·평가 코드에서 읽는다. 정책 ID는 `PILOT_ROLE_AND_SPLIT_SEPARATION_20261126`이다.

- 기준 수립·정답 검수에 사용한 사실만으로 아직 학습하지 않은 대상 모델의 데이터 누출을 단정하지 않는다. AI 라벨링 보조와 평가할 모델에 제공한 학습 데이터·프롬프트·참조 정답은 구별한다.
- 실제 파라미터 학습·데이터 의존 전처리 적합에 쓴 자료를 같은 모델의 미관측 검증·시험으로 쓰지 않는다. 예시·검색 참조 정답·프롬프트·임계값·하이퍼파라미터·모델 선택에 쓴 자료를 그 실험의 미관측 최종 시험으로 보고하지 않는다.
- 노출 이력을 모르면 해당 실험의 노출 검사를 보류한다. 파일럿이라는 이유로 영구 제외하지 않는다.
- 출처 사용 허용은 검수 완료·HOLD 해소·메타 입력 충족을 뜻하지 않는다. 기본 완전 리뷰 내보내기는 미해결 의견이 없어야 하며, 부분 라벨 사용은 별도 마스킹 계약이 필요하다.
- 보존된 `pilot_exclusion_keys`와 과거 `batch_role`은 이력·중복 묶음 자료다. 현재 분할을 결정하는 일괄 제외 규칙으로 읽지 않는다. 현재 지침과 과거 파일럿 주석 버전은 구별한다.

## 현재 파일럿의 상태

- 파일럿은 총 **100건**이다. 원문 단위는 리뷰 1건이며, 의견을 분리해도 리뷰 수는 늘어나지 않는다.
- 기존 1–70번의 과거 사용자 승인 이력과 v0.5에서 이루어진 AI 세분류 이력은 별개다. 이번 버전 이관만으로 기존 AI 재분류를 사용자 검수 완료로 바꾸지 않는다.
- 신규 71–100번은 사용자가 AI 초안을 검수하여 수정·승인한 30건이다. 이 승인은 내용 없음·제외·보류 판단도 포함하며, 모든 문장이 학습용 활성 정답이라는 뜻은 아니다.
- 기존 HOLD 7건과 75번의 HOLD 1건, 총 **8개 보류 의견**을 유지한다. 이는 보류 의견 수이며 보류 리뷰 수와 구분한다.
- 파일럿은 라벨링 단계의 출처다. 그 이름만으로 훈련·검증·최종 시험에서 제외하지 않는다. `CURRENT.json.training_role_policy`를 적용하여 실제 실험별 노출, 검수 상태와 입력 조건을 확인한 뒤 분할·내보내기를 결정한다. 기존 파일럿 원문·주석·미검수·HOLD·`learning_eligible=false` 기록은 보존하며, 이번 정책 변경만으로 학습 가능으로 승격하지 않는다.
- 이 자료는 AI 초안을 사용자가 검수한 파일럿이다. 독립된 두 명의 라벨러가 각각 판정한 정답이나 독립적인 평가용 gold라고 표현하지 않는다.

## 라벨의 단위와 보존 필드

- 독립 라벨은 `leaf_id = aspect_code.subaspect_code`이다. 상위 `aspect_code`는 탐색·그룹 표시용이며 세부 결과를 대체하지 않는다.
- 한 리뷰의 전체 문맥을 읽고 실제로 구별되는 평가 대상별로 의견을 기록한다. 음악·더빙·효과음을 하나의 사운드 감성으로 합치지 않는다.
- 각 의견에는 감성, 정확한 원문 근거와 오프셋, 구체적인 `detail`, 평가 대상 `target`, 조건·시점 `scope`, 검수 이력을 보존한다.
- 분리된 의견은 `source_opinion_id`로 원래 의견과 연결한다. 분리 후 `target`도 각 세부 대상에 맞게 좁힌다. 예를 들어 충돌 의견과 진행 손실 의견에 같은 복합 대상 설명을 그대로 복제하지 않는다.
- 같은 대상의 반복 언급, 불만의 원인과 결과, 예시 나열을 자동으로 여러 독립 의견으로 늘리지 않는다. 서로 다른 대상이 실제로 평가된 경우에만 분리한다.
- 근거는 원문의 정확한 부분 문자열이다. 오타·욕설·줄바꿈을 원본에서 임의로 고치지 않는다. 표시용 정리본을 만들더라도 원문과 구별한다.
- 오프셋은 Unicode 코드포인트 기준 `[start,end)`이다. JavaScript의 UTF-16 문자열 인덱스와 혼동하지 않는다.
- 먼저 명시적 범위 제외 정책을 적용한다. 그 밖의 범위 내 미등록 세부 대상은 설명과 근거를 보존하고 적절한 `UNSPECIFIED` 또는 HOLD를 사용한다. 새 코드를 묵시적으로 생성하지 않고 버전 변경으로 등록한다.

## 감성, 내용 없음, 제외와 보류

- 기본 감성 판단은 리뷰 원문과 그 문맥에 근거한다. Steam 추천 여부는 게임 전반의 추천 메타데이터이므로 개별 속성의 감성 정답으로 자동 복사하지 않는다.
- 부정 추천 리뷰에도 특정 속성의 긍정 평가가 있을 수 있고, 긍정 추천 리뷰에도 구체적인 불만이 있을 수 있다.
- 57번의 ‘낫밷’은 사용자가 승인한 약한 긍정이다. 감성 방향과 강도를 구분해 보존한다.
- 동일한 세부 항목에 긍정과 부정이 모두 있을 때만 해당 세부 집계를 복합으로 표시한다. 두 감성과 각 근거는 삭제하지 않는다.
- ‘스토리가 좋다’, ‘사운드가 좋다’는 대상이 명시된 평가다. 하위 대상을 모르면 그 상위의 `UNSPECIFIED`에 기록한다.
- ‘갓겜’, ‘재밌다’, 일반적인 추천처럼 구체 대상이 없는 표현은 구체 평가 없음이다. 전반적 여론이나 원문의 의미가 없다는 뜻은 아니다.
- ‘뉴비 친화적’처럼 넓은 결과만 제시하고 난도·설명·조작 등 구체 대상이나 근거가 없는 경우 이를 임의로 하위 기능 평가로 바꾸지 않는다. 승인된 84번은 구체 평가 없음으로 유지한다.
- HOLD는 대상·감성 등이 해결되지 않은 상태다. 내용 없음, 부정, 확정 학습 정답으로 바꾸지 않는다. 사용자가 보류 판단을 승인해도 HOLD는 그대로다.
- 제외 문자열은 모델 입력 원문에 남긴다. 제외는 해당 표현에서 추가 라벨을 만들지 않는다는 뜻이며, 그 범위의 모든 토큰을 부정 예제로 만드는 규칙이 아니다.
- API 실패, 원문 잘림, 예측 파싱 실패, 빈 모델 응답을 내용 없음으로 변환하지 않는다.

## 92번의 메타데이터 참조 예외

92번의 효과음 감성은 **원문만으로 부정이 확정된 사례가 아니다.** 사용자가 Steam `voted_up=false`를 함께 참고하여 효과음 부정으로 승인한 예외다. 다음을 함께 보존한다.

1. 효과음이라는 대상의 텍스트 근거와 감성 판정에 사용한 메타데이터를 구분한다.
2. 원문만으로 감성을 확정할 수 없다는 한계, 참조한 추천값, 사용자 승인 이력을 기록한다.
3. 이 예외를 다른 리뷰로 확대해 ‘Steam 비추천이면 모든 속성도 부정’이라는 규칙을 만들지 않는다.
4. 텍스트만 입력한 모델에 92번의 메타 참조 부정을 원문 단독 정답으로 요구하지 않는다. 텍스트 단독 감성 평가와 메타데이터를 제공한 평가를 분리한다.
5. 메타데이터를 제공하는 모델 비교에서는 자체 NLP·GPT·Gemini 모두 같은 필드와 같은 값, 같은 사용 규칙을 받는다. 일부 모델만 추천값을 받는 결과를 같은 조건의 성능으로 비교하지 않는다.

92번도 파일럿 출처만으로 특정 분할에서 제외하지 않는다. 다만 원문 단독 감성 정답으로는 내보내지 않으며, 메타데이터를 동일하게 제공하는 실험에서 검수·실제 노출·분할 검사를 통과한 경우에만 사용할 수 있다.

## 평가 대상의 주요 경계

- 캐릭터 외모는 `CHARACTER.APPEARANCE`다. 귀여움·매력만 언급되면 외모와 성격 중 무엇인지 추정하지 않는다.
- 더빙·음성 연기는 `SOUND.VOICE_DUBBING`, 음악은 `SOUND.MUSIC_BGM`, 효과음이 명시된 평가는 `SOUND.SFX`다. 일반 사운드를 효과음으로 자동 배정하지 않는다.
- 음악이라고만 쓰면 배경음악·주제가 등 구체 형식을 덧붙이지 않는다. 음악에 맞춘 규칙이나 동작 방식에 대한 평가가 별도로 있으면 게임성과 구분한다. 96번은 음악 긍정과 `GAMEPLAY.RULES_SYSTEM` 긍정을 각각 유지한다.
- 번역 표현·정확성·언어 지원은 `OPERATIONS.TRANSLATION`이다. 번역이 맥없다는 표현을 오역이나 운영 대응 실패로 확정하지 않는다.
- 수록곡 제공·곡 구성에 대한 평가는 `CONTENT.TRACK_CATALOG`다. 95번의 원하는 노래가 없다는 불만을 음악 음질·작곡의 부정이나 전체 수록곡 수 부족으로 바꾸지 않는다.
- 타격감은 `GAMEPLAY.HIT_FEEL`이다. 타격음이 명시되지 않으면 효과음 평가를 생성하지 않는다.
- 조작 입력·조작감은 `USABILITY.CONTROLS`다. 83번은 사용자가 수정한 조작 분류를 따른다. 정상 작동하는 조작 방식의 불편과 명시적인 기능 고장을 구분한다.
- 탐험을 직접 평가한 경우 `GAMEPLAY.EXPLORATION`을 사용한다. 91번은 이 세부 항목으로 보존한다. 장르가 탐험형이라는 사실만으로 라벨을 부여하지 않는다.
- 난도 설정 가능성은 `USABILITY.SETTINGS_ACCESSIBILITY`, 체감 난도 평가는 `BALANCE.DIFFICULTY`다. 설정 가능하다는 말이 난도 자체의 호평은 아니다.
- 튜토리얼 설명 부족과 적이 강하다는 평가는 다르다. 실제로 둘을 각각 평가했을 때만 두 라벨을 기록한다.
- 충돌·접속·로딩·진행 장애·진행 손실을 구분한다. 반복해서 저장 파일을 불러왔다는 사실만으로 저장 소실이나 크래시를 추가하지 않는다.
- 모드 사용·설치 이후에 발생한 문제는 그 조건을 보존한다. 기본 게임 전체의 문제나 호환성 원인으로 확대하지 않는다.
- `CONTENT.AMOUNT`는 분량, `VARIETY`는 다양성, `REPETITIVE_GRIND`는 반복 작업, `REPLAYABILITY`는 다시 플레이하는 매력, `LONGEVITY`는 오래 질리지 않는 매력이다.
- 가격 수준과 가격 대비 가치를 구별한다. 한 명의 구매로 함께 이용한다는 평가는 구매·이용 구조다.
- 다른 플랫폼·다른 게임·가정적 이용자의 의견을 현재 게임 작성자의 확정 경험으로 옮기지 않는다. 68번의 모바일판 조작 불만은 PC판 조작 부정이 아니다.
- 외부 게임 지식, 장르, 캐릭터 설정, 인터넷 검색으로 원문에 없는 평가를 보충하지 않는다. 31번의 번역 비유는 실제 현지화 평가가 아니며 내레이터 평가는 기존 HOLD다. 58번의 친구 없음에서 멀티플레이 강제 비판을 만들지 않는다.

## 난이도 해석과 게임 간 비교

서비스 표시 문구:

> 난이도 평가는 해당 게임 이용자들의 체감 의견입니다. 게임마다 이용자층·숙련도·선호가 달라, 이 결과만으로 게임 간 절대 난도를 비교할 수 없습니다.

`BALANCE.DIFFICULTY`는 **작성자가 경험한 난도에 대한 평가**다. 게임의 객관적·절대적인 난도 점수나 게임 간 순위를 나타내지 않는다.

- 높은 난도를 즐겁고 도전적이라고 평가하면 긍정일 수 있다. 높다는 사실 자체를 부정으로 변환하지 않는다. 반대로 쉬움도 항상 긍정은 아니다.
- ‘어렵다’라는 표현의 감성을 전체 문맥으로 판독한다. 원문에서 방향이 해결되지 않으면 장르나 Steam 추천값만으로 확정하지 않는다. 92번의 효과음 예외는 난도에 적용하는 일반 규칙이 아니다.
- 서로 다른 게임의 이용자층, 장르 선호, 숙련도, 진행 단계, 모드·난도 설정, 리뷰 작성 당시 플레이시간이 다를 수 있다. 이 차이를 무시하고 난도 부정률로 게임의 절대 난도를 순위화하지 않는다.
- 예를 들어 GTFO에는 높은 도전을 선호하여 그 게임을 선택한 이용자가 있을 수 있다. 이는 이용자 선택의 가능성을 설명하는 예이며, 모든 GTFO 이용자의 취향이나 해당 리뷰어의 동기를 단정하는 근거가 아니다.
- 작성 당시 플레이시간과 수집 당시 누적 플레이시간을 구분한다. 오래 플레이했다는 사실만으로 숙련자·완주자·장르 선호자로 판정하지 않는다.
- 숙련도·진행 단계·선택 모드 등의 자료가 없으면 미상으로 두고 비교의 한계를 표시한다. 리뷰가 말하지 않은 조건을 메타데이터로 만들어 채우지 않는다.
- 결과에는 표본 수, 비교 기간·언어·수집 범위, 긍정·부정·복합과 미해결 수, 확인 가능한 조건을 함께 표시한다. 게임 간 수치는 각 게임의 관측된 이용자 경험으로 설명하고, 조건이 다른 부정률의 단순 비교를 우열이나 절대 난도의 증거로 사용하지 않는다.

## 집계, 학습, 모델 비교

- 고정된 게임·기간·언어 범위의 **고유 리뷰 키**로 분모와 분자를 계산한다. 의견 수를 리뷰 수나 이용자 수로 바꾸지 않는다.
- 한 리뷰가 여러 세부 항목을 평가할 수 있다. 하위 리뷰 수의 합은 고유 상위 리뷰 수가 아니며, 긍정과 부정 양쪽에 같은 리뷰가 포함될 수 있음을 명시한다.
- 최근 리뷰 수, 수집 원본 수, 전처리 통과 수, 분석 가능 수, 구체 평가 없음, HOLD, 처리 실패를 별도로 보존한다. 서비스 DB로 전달할 때도 집계 범위와 버전을 함께 보낸다.
- Helpful 투표는 노출·공감의 보조 정보다. 감성 정답, 평가의 객관적 정확성, 같은 의견을 가진 고유 인원 수로 치환하지 않는다.
- 파일럿 출처만으로 훈련·시험을 일괄 제외하지 않는다. 같은 리뷰 키·수정본·중복·근접 중복은 같은 분할에 묶는다. 실제 학습, 전처리 적합, 예시 제공, 프롬프트·임계값·모델 선택에 사용한 이력을 실험별로 확인하며, 개발에 사용한 표본을 해당 실험의 미관측 최종 시험으로 보고하지 않는다.
- 사용자 승인, AI 세분류, 메타 참조 예외, HOLD의 출처를 구분한다. AI가 만든 초안을 승인한 자료로 독립 라벨러 일치도나 독립 gold의 신뢰도를 주장하지 않는다.
- 등록 라벨 수는 모델이 학습했거나 검증한 클래스 수가 아니다. 실제 훈련·시험 표본 수와 평가 가능 범위를 별도로 보고한다.
- 자체 NLP·GPT·Gemini는 같은 라벨 사전, 같은 고정 시험 세트, 같은 원문·문맥·메타 입력 조건으로 비교한다. 텍스트 단독과 메타 참조 조건의 결과, 서로 다른 taxonomy 버전의 F1을 섞어 비교하지 않는다.
- 라벨별 Precision·Recall·F1과 support, Macro·Micro F1, 오류 사례, 적절한 혼동표와 학습 곡선을 보존한다. 평가 표본이 없는 항목은 N/A와 평균 산정 정책을 명시한다.

## 설계 참고 자료

아래는 기존 분류 설계의 참고 자료다. v0.6의 세부 항목과 사용자 판정이 이들 연구의 공통 표준이라는 뜻은 아니다.

- [SemEval-2016 ABSA guidelines](https://alt.qcri.org/semeval2016/task5/data/uploads/absa2016_annotationguidelines.pdf): 대상·속성·감성과 근거를 구분하는 구조.
- [Pinelle 외, CHI 2008](https://www.researchgate.net/publication/395238929_Heuristic_Evaluation_for_Games_Usability_Principles_for_Video_Game_Design): 게임 사용성 문제와 세부 문제 유형의 구분.
- [Epp 외, Steam VR 리뷰 연구](https://asgaard.ece.ualberta.ca/papers/Journal/IEEE_2021_Epp_An_Empirical_Study_of_Trends_of_Popular_Virtual_Reality_Games_and_Their_Complaints.pdf): 충돌·최적화 등 문제 유형의 구분.
- [Koehler 외, 2017](https://www.matt-koehler.com/publications/Koehler_et_al_games_2017.pdf): 파일럿을 통해 기존 분류가 담지 못한 평가를 보강한 사례.
