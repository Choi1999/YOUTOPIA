# 한국어 Steam 리뷰 평가 라벨링 v1.2.0 / taxonomy v0.5

2026-11-25. 목적은 리뷰에 실제로 표현된 평가 대상을 추출하는 것이다. 강점·단점이나 시장 인사이트는 여러 리뷰를 집계한 후 해석한다.

## 단위와 필드

- 입력·원본 단위는 리뷰 1건. 전체 문맥을 읽고 한 리뷰 안의 평가를 복수로 기록한다.
- 독립 라벨은 `leaf_id = aspect_code.subaspect_code`이다. `aspect_code`는 탐색·그룹 표시용이다.
- 평가마다 `leaf_id`, `polarity`, 원문 근거와 오프셋, 구체적인 `detail`, 대상 `target`, 조건·시점 `scope`를 보존한다.
- 음악, 더빙, 효과음처럼 리뷰어가 별개로 평가한 대상을 나눈다. 같은 대상의 반복 언급은 새 리뷰로 세지 않는다.
- 분리된 의견은 `source_opinion_id`를 공유하여 하나의 원래 주장·사건에서 파생됐다는 관계를 보존한다.
- Unicode 코드포인트 기준 `[start,end)`이다. UTF-16 기반 JS에서 Python 오프셋을 그대로 slice하지 말고 변환한다.

## 감성과 제외

- 긍정·부정은 원문과 문맥으로 판단한다. ‘낫밷’은 확정된 파일럿 57번에서 약한 긍정이다.
- 동일 세부 항목 안에 긍정과 부정이 모두 있을 때만 세부 집계를 복합으로 표시한다. 원래 양쪽 근거는 유지한다.
- BGM 긍정과 더빙 부정은 서로 다른 결과다. 사운드 복합 하나로 대체하지 않는다.
- ‘스토리가 좋다’, ‘사운드가 좋다’는 대상이 있는 평가다. 세부를 모르므로 해당 상위의 UNSPECIFIED에 기록한다.
- ‘갓겜’, ‘재밌다’ 등 구체적 대상 없는 호평은 현재 목적의 구체 평가 없음이다. Steam 긍정/부정 여론 자체가 없다는 뜻은 아니다.
- HOLD는 평가 대상·감성 등의 미해결 상태다. 내용 없음, 부정, 학습 정답으로 바꾸지 않는다.
- 제외 문자열도 원문 입력에 남긴다. 제외 범위에 걸린 모든 토큰을 부정 예제로 만들지 않는다.
- API 오류·잘린 문장·출력 파싱 실패를 내용 없음으로 변환하지 않는다.

## 경계

- 캐릭터 외모는 CHARACTER. ‘귀엽다’, ‘매력 있다’만으로 외모·성격을 추정하지 않는다.
- 더빙 연기는 SOUND.VOICE_DUBBING. 번역 표현·정확성은 OPERATIONS.TRANSLATION. 번역이 맥없다는 의견을 오역·운영 대응 실패로 확대하지 않는다.
- 원문이 음악이라고만 하면 배경음악·주제가 중 무엇인지 추정하지 않는다. 사운드 일반은 효과음으로 자동 배정하지 않는다.
- 타격감은 GAMEPLAY.HIT_FEEL. 타격음이 명시되지 않으면 효과음 평가를 만들지 않는다.
- 난도 설정 가능성은 USABILITY.SETTINGS_ACCESSIBILITY. 실제 난도의 적절성은 BALANCE.DIFFICULTY.
- 적이 너무 강한 것과 튜토리얼 설명 부족은 다르다. 별개 평가가 실제로 있을 때만 둘 다 부여한다.
- 충돌, 접속, 로딩, 진행 장애, 실제 진행 손실을 구별한다. 현상으로 원인을 단정하지 않는다.
- 모드 설치 후 플레이 불가라는 조건을 보존한다. 기본 게임 전체의 결함이나 호환성 원인, 저장 소실로 확대하지 않는다.
- CONTENT.AMOUNT와 VARIETY, REPETITIVE_GRIND를 구별한다. REPLAYABILITY는 다시 플레이하는 매력, LONGEVITY는 오래 질리지 않는 매력이다.
- 가격 수준과 가격 대비 가치는 다르다. 한 명의 구매로 함께 이용한다는 평가는 구매 구조다.
- 다른 플랫폼·다른 게임의 불만을 현재 대상 게임에 옮기지 않는다. 68번 모바일 조작 불만은 PC판 조작 부정으로 전이하지 않는다.
- 게임 장르·캐릭터 지식·인터넷 검색으로 리뷰에 없는 평가를 보충하지 않는다. 58번 친구 없음에서 협동 강제 비판을 새로 만들지 않는다.
- 31번 번역 비유는 게임 현지화 평가가 아니며, 내레이터의 역할 칭찬은 더빙 연기로 확정하지 않고 기존 HOLD를 유지한다.

## 집계와 학습

- 분모·분자는 고정된 게임·기간·언어 범위의 고유 리뷰 키로 계산한다. 의견 수를 리뷰 수로 바꾸지 않는다.
- 하나의 리뷰가 여러 세부 항목을 평가할 수 있다. 하위 항목 리뷰 수의 합은 고유 상위 리뷰 수가 아니다.
- 최근 리뷰 수, 수집 원본 수, 분석 가능 수, 내용 없음, HOLD, 실패 수를 별도로 보존한다.
- Helpful 투표는 노출·공감의 보조 정보이며 정답 감성이나 의견 인원 수로 바꾸지 않는다.
- 이번 70건은 기준 수립 파일럿이다. 훈련과 최종 시험에서는 review key 단위로 제외한다. 같은 리뷰의 수정본도 제외한다.
- 이전 사람 검수 이력과 새 AI 세분류 이력을 구분한다. 새 항목을 사람이 독립 검수한 gold로 표시하지 않는다.
- 등록 라벨 수는 학습 완료 클래스 수가 아니다. 표본 0건인 효과음 등은 학습 가능·성능 검증 완료로 주장하지 않는다.
- 동일한 라벨 사전·입력 범위·정답·시험 세트를 사용해 자체 NLP/GPT/Gemini를 비교한다. 버전이 다른 F1은 직접 비교하지 않는다.

## 참고 근거

다음은 설계 참고 자료다. v0.5 전체 분류가 이들 논문의 공통 표준이라는 뜻은 아니다.

- [SemEval-2016 ABSA guidelines](https://alt.qcri.org/semeval2016/task5/data/uploads/absa2016_annotationguidelines.pdf): 대상·속성·감성과 근거를 구분하는 구조. 세부 감성 규칙은 이 프로젝트의 판정을 우선한다.
- [Pinelle 외, CHI 2008](https://www.researchgate.net/publication/395238929_Heuristic_Evaluation_for_Games_Usability_Principles_for_Video_Game_Design): 게임 사용성 문제와 세부 문제 유형 구분. 감성 정답 데이터셋 자체는 아니다.
- [Epp 외, Steam VR 리뷰 연구](https://asgaard.ece.ualberta.ca/papers/Journal/IEEE_2021_Epp_An_Empirical_Study_of_Trends_of_Popular_Virtual_Reality_Games_and_Their_Complaints.pdf): 충돌·최적화 등 경험하는 문제의 구별. VR 범주 전체를 그대로 채택하지 않는다.
- [Koehler 외, 2017](https://www.matt-koehler.com/publications/Koehler_et_al_games_2017.pdf): 파일럿에서 기존 범주가 담지 못한 평가를 확인하고 보강한 사례.
